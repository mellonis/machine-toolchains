# Build history

The phase-by-phase record of how this repo was built — what each round
shipped, in what order, and (the part no other surface carries) what was
tried, probed, and rejected along the way.

Lifted verbatim out of `CLAUDE.md`'s preamble on 2026-08-20, where it had
grown to 18.8 KB of a 39 KB file that loads into every session. It is kept
because `CHANGELOG.md` records *what shipped* and the specs record *what was
designed*, but neither records the sequencing or the discarded branches.

**This file is not loaded automatically. Read it when you need to know why
something is the way it is and the durable docs don't say.** Standing
constraints — the rules still in force — were promoted into `CLAUDE.md`'s
topical sections during the same pass and are NOT repeated here; if the two
ever disagree, `CLAUDE.md` is current and this file is history.

Internal artifact: forge references are unrestricted here.

Companion surfaces: `CHANGELOG.md` (four version blocks, ref-free prose),
`docs/superpowers/specs/` (design rationale per round),
`docs/superpowers/plans/` (execution plans), `docs/history.md` (the 2002–2012
Delphi lineage — a different thing entirely, and a durable page).

## The record, v0.4.0 → v0.5.0 (2026-08-17 → 2026-09-XX)

**Current state: v0.5.0, released 2026-09-XX** (crates 0.5.0 plus a fourth crate `mtc-wasm` at 0.5.0; `.pmc` 0.4, PM-1 `.pma` 0.3, `.tmc` 0.1, TM-1 `.tma` 0.3, PM IR 4 / TM IR 3, containers MO 3 / MX 2 / MT 2, both project-manifest schemas 0.2, the VS Code pair at 0.2.0 and the JetBrains pair at 0.2.1, all four `MIN_TESTED_*` floors still at 0.4.0 — the browser release, and the release in which the front ends stopped parsing twice). 285 commits, and **not one version space below the crates moved**: a 0.4.0 program builds unchanged and every artifact either toolchain wrote still loads.

**Master-side housekeeping while the C2 branch ran (2026-08-20 → 08-22).** This file was born on 2026-08-20 (`d09cd59`), when `CLAUDE.md`'s preamble had reached 18.8 KB of a 39 KB always-loaded file and still described v0.3.0 state under a v0.4.0 heading; standing rulings were promoted into topical sections rather than dropped, and four claims were re-derived from the code — among them "eleven per-function optimizer passes, not nine", itself wrong by one and corrected again at the release cut. The toolchain pin followed (`14752d1`): `channel = "stable"` pinned nothing, since rustup re-resolves it per machine, so a fresh CI runner and a laptop months behind compiled one commit with different compilers; 1.98.0 immediately rejected two redundant `use super::opcodes::*;` globs green locally for weeks, and pinning retired the pre-push side-toolchain dance. #92 closed as fixed-upstream-pending-release: IntelliJ 2026.2's frontend-split debugger UI carries no `XDebugSession` in the action's `DataContext`, so LSP4IJ 0.20.1 hid the Disassembly action; the `XDebuggerManager` fallback was verified here on a nightly, but the plugins pin 0.20.1, so nothing shipped. #93, filed off that reading, closed on 08-22: `listing_line` fused address, bytes and mnemonic into one string — right for a terminal, wrong for a debug adapter that has `instructionBytes` — so `listing_parts` exposes the four components, `listing_line` composes from it byte-identically, and both adapters draw from the same parts. Wide instructions gained two-column wrapping, forced by tape count (a sixteen-tape `wrmv` is 25 bytes and a 99-character operand); `run --trace` is pinned to one row per retired instruction. #94 was recorded as open work in the same commit.

**The worked examples (2026-08-30).** The flagship moved into `docs/examples/brainfuck-utm/` as `brainfuck-utm-handwritten.tma`, so the name says what separates it from the compiled `.tmc` it is proved equivalent to; the plans and specs kept the old path deliberately, recording what was true when written. Five programs joined it: four spellings of one RPN calculator — stdlib binary, four hex digits in one tape, those digits as a register over four tapes, four tapes that ARE the stack — at 788,375 / 279 / 195 / 164 steps on one addition, what the last three buy in tape count paid for in vector width (fourteen cells per rule at the far end); plus `pow2`, flat unary, no reuse constructs. Three differentials compare whole final tape snapshots rather than the one value a case checks — `-O0` against `-O1`, the three bound-call lowerings, a disassemble/reassemble round trip — each with its limits in prose. `bf6178c` ported the case tables into the suite, reading the same tables the shell runner reads so the two cannot assert different things, and stricter in three ways: a `trap` case must trap on a MISSING TRANSITION, so an exhausted step budget can no longer pass as a diagnosis; each example is its own test; an over-long expected value lives in a sidecar both harnesses read. A doc round (`38ca36f`) wrote down a rule that had lived only in a source comment: canonical `dis` prints a linker-narrowed site under its far mnemonic, because far is the only form the assembler accepts and re-linking re-derives the narrowing — which is what keeps dis → asm → link byte-exact.

**The C2 green-tree migration (#14, spec `docs/superpowers/specs/2026-08-17-c2-green-tree-syntax-design.md`, twelve plans, ~210 commits, merged `69fe5ec` on 2026-08-31).** C1 had left each crate a hand-typed CST plus an owned AST that `lower_cst` copied into — two trees per crate. An audit corrected #14's own scope claims first: the optimizer and codegen sit behind the IR firewall and never move; the CSTs already share their statement/rule internals, so the duplication is container-level; and the owned AST survives BY DESIGN, being also the synthesized intermediate a pass hands on, which views can never represent. Rejected: an accessor layer over the existing CSTs (buys none of the shared infrastructure), and depending on `rowan` or vendoring a fork (the minimal-deps stance holds, and core already hosts this kind of language-agnostic framework). Delivery was ruled one branch, both crates, every commit green. Plan 1 built the core framework, plans 2–6 took `.pmc` from kind space to `fmt` (emission woven into the existing parser through its own `bump()` hook), and plans 7–11 did the same for `.tmc` with two differences bought with the PM side's costs: the program generator landed four plans before its first consumer, because on PM two Critical bugs had passed six plans and eight mutation-armed reviews while living in shapes no hand-written fixture contained, and the doc-run retro-wrap shape was RULED rather than discovered, since a tree dump would only have read back an unexamined default. Plan 12 closed it — both differential oracles and both CSTs deleted, `parser::parse` reduced to a wrapper over lex → green parse → extract, the stdlib roster and driver scan switched from respelling that route to calling it, and the coverage floor rebuilt from the generator, with the chosen/derived partition (which a subset check had left able to lose a label's two-directional compare silently) closed to a literal set proven red by name. Fidelity is pinned now by `text() == source` over the shipped corpus AND generated programs, extraction's written-out literals, and the goldens; no second front end is left to compare against. Much of the cost was review: plan 8's task 3b was argued from a false premise (extraction never splits flat runs — it reparses a node's extent through the parser's own production) though the task was right; plan 10 undercounted the retro-wrapping kinds as four where the measured figure is seven kinds over nine sites, and its exit criterion would not have been met by its own steps, since deleting `parse_cst` removes one parse and leaves another unless the tree is retained; a view-census fixture claimed to catch a view added later and provably could not, so it became a census against the contiguous discriminant run `32..=46`; an invented justification for the checkpoint position was removed before it reached the remaining briefs; and "contextual keywords" reached two briefs and a shipped doc comment before being disproved twice — the only contextual word is the `deprecated` attribute name. Fixtures were run through the real tool before shipping in every plan, which is how the defective ones were caught (`erase` is not a builtin; `use` accepts no doc run; an all-kinds fixture with no namespace would have panicked the cast test). Three printer defects surfaced in whole-plan review rather than in any suite: the `.pmc` green printer duplicated an open-brace comment nothing claimed — and `pmt fmt PATH` rewrites in place, so five passes appended five copies and `--check` could never go green — stacked labels on separate lines took the own-line break and moved every command in the body left, and header-interior comments were DELETED where C1 relocated them, invisibly, since token equivalence lexes without comments and idempotence holds on lossy output. All three were pinned at the fixed point rather than after one pass, the fmt generator was widened into the space they lived in, and the loss class was closed structurally: both printers now end, in debug builds, by comparing the multiset of normalized comment texts lexed from source against the output, each assert proven to bite by mutation. The merge also landed the ruling that a plan's `Task N` numbering is internal notation exactly as `spec §N` is.

**Never moving a comment: `.tmc` (#98) and `.pmc` (#96).** The `.tmc` half was designed in the C2 endgame and executed after the merge, on an audit (`docs/superpowers/specs/2026-08-30-tmc-comment-audit.md`) measuring all 61 grammatical positions in both comment flavours over three passes, then ported into the suite as `crates/turing-machine/tests/comment_positions.rs`. **The editor rounds (2026-09-02, #110 and #111).** Under plugins 0.2.0 every LSP feature of both JetBrains plugins was silently dead — LSP4IJ started the server for an opened file and never sent `textDocument/didOpen`, on 0.20.1, 0.21.0 and a 0.21.1 nightly alike. Root cause, isolated by A/B against the July 0.1.x build on the same LSP4IJ and server: 0.2.0 had made the file types `LanguageFileType`s over marker languages with no parser definition, and the platform then builds a plain-text PSI file whose language disagrees with the file's — a document the bridge never connects. Each language now owns the smallest parser definition it can (word, whitespace and punctuation tokens under one file node, nothing read for semantics), which also made the Cmd/Ctrl-hover underline identifier-precise, since the platform underlines the PSI element under the caret: the whole-file underline both READMEs recorded as an upstream limitation was ours. Both manifests additionally register, for their own languages, the per-language extensions LSP4IJ provides only for plain text and TextMate — semantic tokens behind quick documentation, structure view, folding, code blocks, parameter info. The Kotlin trap met on the way is why the fields are `ownFileType`/`ownLanguage`: inside an `object : PsiFileBase(...)` a bare `fileType` resolves to the object's own synthetic property, and the override recursed until the IDE ran out of stack. #111 ruled the navigation question the same day: every `as NAME` is a declaration and what it stands for is one hop away — a `goto` lands on its graft statement's alias, whose target name is the hop to the graph; a call written through a `use` alias lands on the alias, whose path is the hop to the imported declaration. The statement is where the binding lives, two instances of one graph stay distinguishable, and the rule matches what every editor means by "definition". A docs split rode along: VS Code renders an extension's README as its page and more than half of each was maintainer material, so the build-and-sideload sections and manual checklists moved verbatim into a `MAINTAINERS.md` beside each, excluded from the vsix.

**The standard-library contracts (#112, 2026-09-02).** The embedded TM-1 library declared a `writes`/`preserves` clause on 15 of its 40 exported tapes — the four `goTo*` families and the bare `invertNumber` — and left the other 25 making no machine-checked claim at all. Every export now carries one, each EXACT: it names precisely the symbols some run of the routine writes, derived from the footprint inference over the library's own bodies and held there by the compiler's contract check. `tmt fmt` wrapped the fourteen signatures that outgrew its width, and the compiled object is byte-identical before and after — a clause changes what the compiler checks, never what it emits. The second half was the reason to bother: the inference contributed the caller tape's WHOLE alphabet for any call whose target lay outside the compilation unit, so hovering any routine that touched the standard library reported it as writing every symbol — the rpn example's `seekStart`, which only calls `goToNumbersStart` and leaves the tape unchanged, read as writing all five symbols of `bin`, and now hovers as `writes n: {}`. An external callee whose resolved signature is visible now contributes its declared effective set projected through the binding exactly as a local callee's inferred set is; a callee nobody vouches for still contributes everything, and objects at the link boundary carry no contracts and stay conservative — recorded as the limit. Believing a declared clause is as sound as believing a local body, because the callee's own contract check held that body to the promise. `CompileOptions` gained `ExternalContracts { Stdlib, None }`, `Stdlib` by default, the library's own analysis passing `None` because a default of `Stdlib` would re-enter the `OnceLock` while it initializes. That `OnceLock` produced the round's lesson: the one-parse pin counts green parses on a thread-local counter, and the contract check now resolves the embedded stdlib on the first `did_update` in a process, so under nextest — one process per test — that parse landed on the test's own thread and the count read 2, while under `cargo test` an earlier test in the shared process had usually warmed it and it read 1. The pin passed locally and failed in CI; the fix warms the stdlib before zeroing the counter, and the standing lesson is that the final gate is `cargo nextest run --workspace`, never `cargo test` alone.

**The browser arc, toolchains half (#6, 2026-09-02).** It opened with a gate rather than a feature: the sans-I/O core was designed for the browser and the compilers and linker touch no filesystem or clock, so the library crates already built for `wasm32-unknown-unknown` unchanged — a property nothing enforced until the target was pinned in `rust-toolchain.toml` and CI built for it (`24fd2db`). The gate is compile-only and says so, because `std` on this target is a stub OS layer: a filesystem or clock call leaking into a library would still build and only misbehave in a page. The design (`docs/superpowers/specs/2026-09-02-wasm-binding-design.md`) rests on a measured probe — a throwaway `cdylib` with raw `extern "C"` exports, fat LTO, `panic = "abort"`, stripped, `wasm-opt -Oz` — at 64 KB / 26 KB gzipped for the VM alone, 489/200 with PM-1's chain, 676/272 with TM-1's, and 795 KB / 321 KB gzipped for both full chains, against the consuming demo's own mermaid chunk at 439 KB gzipped: the compilers ship in the browser, and a VM-only module is not needed for size and was not built. Nine decisions were ruled with what each rejected — a release artifact built by this repo's CI (rejected: an npm package, a second publishing flow for one consumer; the demo building the wasm itself, on whichever laptop ran it), build + run + dis + lint + fmt on both toolchains (rejected: build+run only, leaving the ip view nothing to highlight), wasm-bindgen classes with plain JS values built through `js-sys` so `serde_json` stays out of the module and the `.d.ts` is generated (rejected: flat functions over JSON strings, ~100 KB and hand-written types; `serde-wasm-bindgen`, whose types degrade to `any`), tapes owned in Rust behind a one-variant device slot so a JS device can join later, UTF-16 half-open offsets because CodeMirror takes them directly (rejected: LSP line/character, byte offsets), and a Node smoke test of the real bundle (rejected: headless Chrome for what Node can prove). Rulings during execution: `Tm1` is width-agnostic — its constructor only validates the tape count and retains nothing — so the per-tape-count registry cache collapsed to one leaked registry, a `thread_local` because `Arch` carries no `Send + Sync` bound (R2); a wasm-bindgen getter returning `Result` was settled empirically on 0.2.127 by a scratch probe rather than reasoned about a second time (R1). The whole-branch final review returned Ready-with-fixes over 24 commits — no Critical, four Important: the `.d.ts`'s optional parameters were not optional, the trap kind was sampled once, `release.yml` attached the bundle without running the smoke test the push gate runs, and the smoke test was thin on getters, breakpoints and snapshots. Its measured Minors were the interesting part: `pump(2**32)` truncated to a 0 budget and spun a page's loop forever, `maxSteps: -1` saturated to an instant trap nobody asked for, and `cells: {}` silently seeded a blank band. All three were fixed (R8: the budget becomes `Option<f64>` rejecting non-finite or below 1) and — the part that mattered — made discriminating: those fixes live entirely in the wasm-bindgen layer, which the native suite cannot reach, so the smoke script was the only thing that could exercise them and did not; three checks were added and verified by hand against each fix reverted in turn. The shipped bundle measures 1.12 MB raw and 450 KB gzipped — some 130 KB gzipped over the probe, for the glue, the `js-sys` object building and `serde_json` reaching in through `mapJson` — under a 1 MB gzipped ceiling the smoke test enforces; the size audit was ruled a follow-up rather than part of the fix wave (R6).
