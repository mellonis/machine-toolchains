# Release 0.3.0 (cut #8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.3.0 — the release that delivers the whole TM-1/tmt arc plus the PM volatile/async/footprint rounds — closing #8 and #79: code-audit sweep, full docs audit, CHANGELOG with the version block, crate/plugin bumps, tag, GH release with all four editor-plugin artifacts.

**Architecture:** This is a release round, not a feature round: two audit stages (code hygiene, docs verification) produce fix waves; then one bump+CHANGELOG commit; then the cut mechanics. Behavior neutrality is a standing gate — nothing in this round may change what the toolchains compute.

**Tech Stack:** Rust cargo workspace (3 crates), npm/vsce (2 VS Code extensions), gradle/JBR (2 JetBrains plugins), gh CLI.

## Global Constraints

- **Published-docs policy**: `README.md`, `CHANGELOG.md`, `docs/` reference pages are ref-free and forge-agnostic — no issue/PR numbers, no hosting-provider URLs, substance in prose. `CHANGELOG.md` is in that bucket deliberately. Internal artifacts (`docs/superpowers/`, `.superpowers/`) are unrestricted.
- **No Claude / AI attribution** in any artifact — commits, CHANGELOG, release notes, issue comments.
- **Conventional commits with scope**: `docs(...)`, `chore(release)`, `polish(...)`, `test(...)`.
- **Behavior neutrality**: Tasks 1 and 3 are comments/docs/test-relocation only — `cargo build` outputs must be unaffected; the full test suite is the proof.
- **Gates before every merge-bound state**: `cargo fmt --check`; `cargo clippy --workspace --all-targets -- -D warnings`; `cargo +1.97.0 clippy --workspace --all-targets -- -D warnings` (CI runs newer stable than local 1.94); `cargo build -p mtc-core --no-default-features`; `cargo nextest run --workspace` (or `cargo test --workspace`). Rationale: these are protocol/capability surfaces where silent tolerance of unknown members is wrong (a device must execute every command; a pump loop must handle every event; a capability defaults off only because `Default` says so). Growth is a deliberate, compile-visible, semver-visible event. Task 1 records the contract as doc comments.

**Files:** read-only over `README.md`, `docs/core.md`, `docs/formats.md`, `docs/history.md`, `docs/lsp.md`, all of `docs/pmt/*.md` (9), all of `docs/tmt/*.md` (9). Findings land in `.superpowers/sdd/2026-08-10-release-0.3.0/audit-<group>.md`.

2. **Parser → docs flag sweep** (CLI pages): extract the real parser's accepted flags per subcommand (from `cli/*.rs` match arms and `--help` output) and set-compare against the page both ways.
3. **Roster set-compares**: lint codes from BOTH `###` headings and table rows vs the registries; opcode lists vs the arch tables; stdlib routine lists vs the embedded sources; version constants vs the page headers.

6. **LSP pages**: drive a real `initialize` handshake against `pmt lsp` / `tmt lsp` and compare advertised capabilities against the page.
