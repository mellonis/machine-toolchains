# Binding Arc, Phase 3a — Compiler and Headers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Teach the `.tmc` compiler to PRODUCE the symbolic forms phases 1 and 2
taught the object format and the linker to carry, and to CONSUME declarations
that arrive as source — a new `.tmh` header kind, sibling `.tmc` files, and the
interface sections of library objects. Two "not yet lowered" error codes are
retired by building what they stood in for: a bound call into an external
callee, and a routine that hands control to its own `state` parameter.

**Architecture:** One data path, opened at both ends. *Outward:* the compiler
always writes an interface section (`.param` lines, exported alphabets, the
exit count and the `returns` bit) and emits a symbolic bound site when the
callee is external — parameter names instead of positions, glyph labels instead
of indices — which the phase-2 pre-pass already resolves. *Inward:* a
declarations table, assembled from `--extern` files, sibling sources, library
objects and the embedded `std.tmh`, reaches `resolve_program` through a widened
`ExternalContracts`, so alphabet imports, named maps, library graph grafts and
early binding checks all read one source of truth. The IR gains the fields both
directions need in a single versioned encoding change (v3 → v4). Nothing in
`crates/core` moves except two corrections to the shared layer, each the other
half of something the compiler now does: the `.tma` glyph literal widens to
spell every label a `.tmc` alphabet can hold, and one link warning covers the
one shape in which a header's `noreturn` can be a lie.

**Tech Stack:** Rust (pinned toolchain in `rust-toolchain.toml`), `proptest` for
the IR round trip, `cargo nextest run --workspace` as the final gate, no new
dependencies.

**Spec:** `docs/superpowers/specs/2026-09-13-issue-95-binding-analysis.md` —
"Item 1", "Item 2", the `state`-parameter half of "Item 3", "### Predicates"
(P6, P7, P9), the "**Compiler.**", "**Lint.**" and "**CLI.**" paragraphs of

  the one shared surface is `crates/core`, and **exactly two tasks touch it —

## Established facts this plan builds on

Verified against the working tree at `e25e91d` on 2026-09-15. An implementer
may rely on these without re-deriving them; each names its evidence.

1. **A `.tmc` glyph literal's content is ANY non-empty UTF-8 string; a `.tma`
   glyph literal refuses anything but one character.** Not an emoji corner
   case — `docs/tmt/language.md:72-76` states the `.tmc` rule normatively ("one
   grapheme, an emoji, or a multi-scalar sequence are each a single glyph"),
   `crates/turing-machine/src/lexer.rs:701-710` pins the ZWJ case, and
   `crates/core/src/asm/lexer.rs:954` (`glyph_rejects_multi_char_content`) pins
   the `.tma` refusal. Run end to end: an alphabet `{ '_', 'ab', '->' }`
   compiles clean, while a `.param` carrying `'ab'` — or `'👨‍👩‍👧'` — is
   `error: not assembly text [raw-line]`; the same file with a single-scalar
   `'🙂'` assembles and dis→asm round-trips byte-identically (log rows E2–E4,
   H1–H2). **The collision is dormant only because the compiler emits no
   `.param` today**; Task 3 would wake it, so **Task 2b removes it first**.
1a. **Core's own glyph-list parser already accepts multi-character elements and
   already rejects multi-character range endpoints.**
   `crates/turing-machine/tests/glyph_notation_parity.rs` pins
   `mtc_core::formats::parse_glyph_list` against the `.tmc` alphabet resolver in
   both directions: its accepted CORPUS carries `"'ab','c'"` (`:16`) and its
   `BAD` list carries `"'ab'..'z'"` (`:55`). **Verified green, 4/4** (log row
   H3). Since `docs/formats.md:698-701` says a `.param`'s `(…)` group IS that
   notation, the `.tma` lexer is the sole outlier — which is what makes Task 2b
   a correction rather than a widening.
2. **The compiler emits NO `.param` and no interface section** (phase-2
   established fact 3, re-verified: `tmt compile zwj.tmc -S` prints `.routine`
   lines and no `.param`, log row E1). So every glyph-level linker check
   landed in phase 2 is structurally dormant on the shipped corpus until
   Task 3.
3. **The shipped corpus is glyph-equal, not merely cardinality-equal.**
   `docs/examples/rpn/rpn.tmc:52` `alphabet bin { '_', '^', '$', '0', '1' }` is
   position-identical to `crates/turing-machine/src/stdlib/std.tmc:53`
   `export alphabet symbols { '_', '^', '$', '0', '1' }`. So Task 3's emission
   raises no `glyph-mismatch` on the four shipped plain `call std::` sites
   (log row G). This is a prior, not a substitute for Task 3's own measurement.
4. **`IrTape` does not carry glyph labels.** `ir.rs:112-120` is `{ name,
   alphabet, cardinality, volatile }` — `alphabet` is a NAME, documented as
   "presentation only". `codegen::emit_program`'s only input is `IrProgram`
   (`codegen.rs:158`). So `.param`'s glyph lists cannot be emitted without an
   IR addition; that is why Task 2 exists and why it is bigger than the spec's
   four-variant list.
5. **`ExternalContracts::modules()` returns `Vec<&'static Resolved>`**
   (`compiler.rs:2121-2128`), `'static` only because the stdlib is an
   `OnceLock`. Header declarations are per-invocation owned data, so the enum
   must become owned declarations with borrowed views — Task 1.
6. **`parse_reuse` always demands a `{ … }` body** (`parser.rs::parse_reuse`, `:1441` today), and
   that is the WHOLE header grammar delta: a `.tmh` carrying `export alphabet`,
   `namespace`, a `?` doc line, a signature and a `writes` clause fails at
   `expected '{' to open the body, found ';'` — column 61 of line 4, i.e. past
   everything else (log row C1). **[tool-verified]**
7. **`map` is already a reserved word** (`lexer.rs:35`, in `RESERVED[27]`), and
   a top-level `map` declaration fails with
   `expected a top-level declaration, found 'map'` (log row C2). So named maps
   cost a top-level arm, not a reserved-word bump. **[tool-verified]**
8. **The symbolic `.tma` the compiler must emit assembles, links and
   round-trips today.** The spec's own sketch — `mylib.tma` with `.param num,
   ('_','0','1'), writes=('0','1')` and `app.tma` with
   `call mylib::plusOne [num: 1{3->'0', 4->'1'}]` — assembles both sides, links
   with `1 composite(s), 0 stamp(s), 4 B compose table`, and disassembles back
   to the same operand (log rows D1–D4). **[tool-verified]** So Task 10 has a
   fixed target, not a guess.
9. **`exits=(…)`, `noreturn` and `retx #k` assemble and link today**
   (log rows D5–D6): `.routine sub, tapes=1, alpha=(3), exits=2, noreturn` with
   `call sub [t: 0] exits=(hit, miss)` links under `--call-mech mono` as
   `1 stamp(s)`. **[tool-verified]** Task 11's emission target is likewise fixed.
10. **The expander already dedups identical graft sites, and lint says nothing.**
    `expand.rs:1310-1314` keys an instance by
    `target ++ 0 ++ composite.key() ++ 0 ++ cont_key(cont)` and aliases on a
    hit (`:1321-1327`); two identical sites emit one subgraph and `tmt lint`
    reports only the two unrelated `unused-*` findings (log rows F1–F2).
    **[tool-verified]** `duplicate-graft-instance` keys on exactly that tuple,
    so it has no false positives by construction.
11. **The phase-2 predicate `tail-call-no-continuation` needs already exists.**
    `crates/core/src/linker/stamp.rs:1378-1389` (`check_splice_site`) computes
    `continuation(caller.blob.len(), addr).is_none() && callee_can_return(syntax,
    callee)`; `callee_can_return` (`:1339-1344`) reads the callee's `returns`
    bit and falls back to a body scan when the bit claims `noreturn`
    (ruling 33). The warning is that predicate applied to a `Plain`/`Bound`
    site. **It needs no header** — only the callee's `returns` bit and the
    caller's blob length, both already on the wire.
12. **`find_library` looks for `<name>.tmo` only** (`cli/build.rs:452-460`) and
    errors "`library X not found on the -L search path`" otherwise. Header-only
    libraries (Task 15) widen exactly this function.
13. **The interface section's `enters`, `leaves` and `opaque` fields already
    exist on the wire** (`crates/core/src/formats/object/mod.rs:239-250`,
    landed by phase 1). 3a writes `None`/`false` into all three and leaves them
    as 3b's seam; the reader already rejects a present-but-empty `enters`/
    `leaves` list as `Malformed`.
14. **`Interface.imports` is dormant** — the FIELD, `Interface.imports` on the
    `Interface` struct (`mod.rs`, around `:286`; `struct ImportedAlphabet` that
    it holds is a few lines above, at `:261-270`). The linker's `AlphabetDrift`
    check is live but no writer fills the list. Task 8 fills it.
14a. **`preserves` has no peer on the wire.** `RoutineInterface` carries
    `writes` and nothing else about the write set (`object/mod.rs:239`), while
    `preserves { … }` is a first-class signature clause
    (`parser.rs::sig_param`; `docs/tmt/language.md`, contract clauses) whose
    effect is subtractive — `compiler::declared_effective` is `writes`, or the
    whole alphabet absent the clause, minus `preserves`. **The format has
    therefore already ruled that `preserves` collapses into the effective set**,
    which is what Task 2's F1 ruling makes explicit for the IR and the header.
    `std.tmc:375` and `:526` (`invertNumber`) are the shipped case, and they are
    `preserves`-only — no `writes` clause at all.
15. **Every `export routine` in `std.tmc` reaches `return`.** Verified during
    the pre-flight scan; recorded so nobody re-derives it. Consequence:
    Task 12's `noreturn` emission moves neither the `std.tmh` pin nor the
    compiled-stdlib object, so both gates hold exactly through that task.
16. **`docs/tmt/asm.md` exists**, so Task 2b's conditional edit to it is
    actionable rather than a maybe. Also recorded from the pre-flight scan.
17. **`ExportedGraph.digest` is on the wire and nothing computes it.**
    `docs/formats.md:253,369,684` specify the field and the `.graph`/`.grafted`
    directives; no code produces a canonical-text CRC-32. Task 4's printer
    becomes that text's single source of truth, which is why Task 13 depends
    on Task 4.

### Task 1: Declarations become owned data (no behaviour change)

**Why first.** Everything the compiler learns from outside its own unit —
alphabets, maps, routine signatures, graph bodies, `writes` contracts — arrives
through one table. Today there is exactly one such source, the embedded stdlib,
and it is `&'static` because it lives in a `OnceLock` (Established fact 5).
Headers are per-invocation owned data. Widening the carrier BEFORE any consumer
exists keeps the refactor honest: it must change no behaviour at all.

**Requirements**

- `ExternalContracts` becomes a struct carrying owned declaration modules plus
  each one's provenance; the two old spellings survive as constructors so no
  call site's INTENT changes:
  - `Declarations::stdlib()` — today's `ExternalContracts::Stdlib`.
  - `Declarations::none()` — today's `ExternalContracts::None`, still what
    `stdlib::object()` and `stdlib::analysis()` pass to avoid recursing into
    their own `OnceLock`.
- The borrowed view `resolve_program`, `check_contracts` and
  `footprint::infer_resolved_with` read is a `&[&Resolved]` produced by one
  method, exactly as `modules()` produces one today.
- **Provenance is carried from the start**, even though nothing reads it until
  Task 13: each entry records whether it came from the embedded stdlib, an
  `--extern` file (with its path), a sibling source, or a library object. A
  diagnostic that has to say "declared by `use`, but its declarations were not
  given" (Task 8) and a digest check that has to name the library (Task 13)
  both need it, and retrofitting it would touch every construction site twice.
- `CompileOptions.externals` changes type. Every construction site follows:
  `compiler.rs`, `stdlib/mod.rs:57-73` and `:104-121`, `cli/build.rs:150`,
  `cli/driver.rs:426`, `:366`, `:716`, and **`crates/wasm/src/inner/`** — the
  browser binding compiles `.tmc` through this same path and carries a
  stdlib-object byte pin plus the `inner/`-is-free-of-`wasm-bindgen` test.
- `Declarations` is `Clone` but not `Copy` (it owns `Resolved`s), so
  `CompileOptions` loses `Copy` on that field. Check every `..Default::default()`
  and every by-value pass; prefer `&Declarations` in function signatures.

### Task 2: IR v4 — the encoding

**Why here.** Two later tasks (10, 11) fill IR variants, and R-3a-2 puts the
`TM_IR_VERSION` bump in "the task that changes the IR encoding" — singular. So
the whole encoding lands once, with its round trip, before any consumer. This
is the shape phase 1 used for the object format.

**Requirements**

Six additions, three of them beyond the spec's own list — see "Decisions for
the controller" (D2) for why:

| Field | Type | Consumer |
|---|---|---|
| `IrTape.glyphs` | `Vec<String>`, len == `cardinality` | `.param` glyph lists (T3) |
| `IrTape.writes` | `Option<Vec<String>>` — **the EFFECTIVE set** | `.param`'s `writes=(…)` (T3) |
| `IrWorld.exits` | `u8` | `.routine`'s `exits=` (T11) |
| `IrWorld.returns` | `bool` | `.routine`'s `noreturn` (T12) |
| `IrTransition::ReturnExit { exit: u32 }` | new variant | `retx #k` (T11) |
| `IrTransition::CallThen.exits` | `Vec<u32>` (state ids) | the `exits=(…)` operand (T11) |
| `IrTapeBinding.param` | `Option<String>` | a symbolic entry (T10) |
| `IrMapPair.dst` | `IrMapDst::{Index(u32), Label(String)}` | a glyph-labelled pair (T10) |

- **`IrTape.writes` carries the EFFECTIVE set, and `preserves` never reaches
  the IR** (controller ruling, 2026-09-16 — F1). `preserves { … }` is a peer of
  `writes { … }` on a signature tape parameter, and the effective permission is
  `writes` (or the whole alphabet, absent the clause) MINUS `preserves` —
  `compiler::declared_effective`. The wire has already ruled on this:
  `RoutineInterface` carries `writes` and no `preserves` peer. So:
  - fill `IrTape.writes` from `declared_effective`, **never from the raw
    clause**. On the raw reading, `std::…::invertNumber` — which declares
    `preserves { '_' }` and **no** `writes` clause (`std.tmc:375`, `:526`) —
    would emit no `writes=` suffix and publish an interface permitting a write
    its own source forbids. That is the bug this ruling forecloses.
  - a `preserves`-only clause therefore yields *the alphabet minus the
    preserved glyphs*, which is a `Some`, not a `None`;
  - **neither clause** yields `None` and no `writes=` suffix — the only case
    that does;
  - `preserves` is source-level sugar with no representation in the IR, on the
    wire, or in a header. Tasks 3, 4 and 7 each restate the consequence for
    their own surface.
- `#[serde(default, skip_serializing_if = …)]` on every added field that has a
  natural empty value, so a v3 document with none of them deserializes into a
  v4 struct unchanged — **but the version field still moves to 4**, because the
  encoding's vocabulary grew. `IR_VERSION` is the acceptance contract, not a
  compatibility hint.
- `TM_IR_VERSION` `3` → `4` at `ir.rs:65`; the two stamping sites (`:473`,
  `:1155`) follow for free.
- **3b's seam, stated not built:** `IrTape` will gain `enters`, `leaves` and
  `opaque` in 3b. They are NOT added here — a field written as `None` by
  everything is not a seam, it is dead weight. **3b needs no version bump**
  either: v4 is unreleased, so those fields join the v4 encoding exactly as the
  language version stays 0.2 (R-3a-2, controller ruling 2026-09-16).
- Nothing in this task PRODUCES a new variant. Lowering still refuses a
  `state`-parameter continuation and an external binding; the fields are filled
  with their empty values. This is what keeps the task independently reviewable.

### Task 2b: The `.tma` glyph literal catches up with the glyph it must spell

**Why this task exists, and why it is immediately before the emission task.**
The controller OVERRULED this plan's original proposal to declare a fourth
text-expressibility exception (D1). The notation is widened instead, so that
Task 3's corpus measurement runs over a `.tma` that can spell every label a
`.tmc` alphabet can hold.

**The case, in four facts.** This is not an emoji corner case:

1. **`docs/tmt/language.md:72-76` already defines a `.tmc` glyph literal's
   content as "any non-empty UTF-8 string"** — "so one grapheme, an emoji, or a
   multi-scalar sequence are each a single glyph". `'ab'` and `'->'` are
   ordinary legal glyphs, not exotica. **[tool-verified]**: an alphabet
   `{ '_', 'ab', '->' }` with rules matching and writing them compiles clean
   (log row H1).
2. **Core's OWN glyph-list parser already accepts them.**
   `crates/turing-machine/tests/glyph_notation_parity.rs:16` carries `"'ab','c'"`
   in its accepted CORPUS, pinning `mtc_core::formats::parse_glyph_list` and the
   `.tmc` alphabet resolver as agreeing on it. **Verified green** (4/4, log row
   H3). And `docs/formats.md:698-701` says the `(…)` group of a `.param` line
   **is that notation**. So the `.tma` lexer contradicts the page that defines
   the very list it is lexing.
3. **The existing exceptions degrade by dropping data; this one produces text
   the assembler REFUSES.** An exported alphabet prints as a comment and
   reassembling silently omits it — lossy, but the output is still valid
   assembly. A multi-character label makes `tmt dis` emit a `.param` line that
   `tmt asm` rejects outright (`error: not assembly text [raw-line]`, log rows
   E2/H2). That is a worse failure class than the gate was written to tolerate.
4. **Phase 1 already knew the wire carries strings** — `RoutineInterface.glyphs`
   is `Vec<Vec<String>>`, and the caveat bullet at `docs/formats.md:727-730`
   exists precisely because the format outran the notation.

**Requirements**

- **One rule in both lexers:** a `.tma` glyph literal is any **non-empty**
  content in single quotes, with exactly two escapes (`\'` and `\\`). Empty
  `''` stays a lex error; an unterminated literal stays junk. The change is in
  `crates/core/src/asm/lexer.rs` at the guard behind
  `glyph_rejects_multi_char_content` (`:954`).
- **A `..` range endpoint must still be a single character or a bare number.**
  `'ab'..'x'` stays an error under the existing same-kind check — and it is
  **already pinned in both directions**:
  `glyph_notation_parity.rs:55`'s `BAD` list carries `"'ab'..'z'"`, asserted
  rejected by core's parser AND by the `.tmc` resolver. Widening the literal
  must not widen the range rule; that test is the guard, and this task adds the
  `.tma`-side twin.
- **This is ONE OF THE PLAN'S TWO `crates/core` diffs** (this task and Task 16;
  Global Constraints names both), justified in the same terms as the other:
  arch-agnostic — a lexer rule in the shared asm layer, under the interface

**Requirements**

**Requirements**

- `resolve_binding` (`ir.rs:709-806`) keeps today's index path for an in-unit
  callee and takes a symbolic path for an external one. The refusal at
  `:735-741` is deleted and `CompileErrorKind::ExternalBindingUnsupported` with
  it.
- **What the symbolic form carries** (P6, and the phase-1 wire rulings):
  - `param` — the callee's parameter NAME, from the declarations table.
  - `caller_tape` — a physical index, as today. Always numeric: it names the
    CALLER's own band, which the compiler knows.
  - `src` — a caller-alphabet index, as today. Same reason.
  - `dst` — the callee glyph LABEL, because the callee's index space is the
    linker's to resolve.
  - **An omitted map emits NO pairs** (P6) — index identity, and the linker's
    item-4 warning stands guard. Do not "helpfully" expand an omitted map into
    identity pairs; that would silence the warning the arc exists to raise.
  - A named map (Task 9) expands to its pairs first and is then emitted by the
    same path — no third form.
- **Entries are named or positional, never mixed** in one list (phase-1
  ruling; the assembler enforces it and the pre-pass refuses a mix). Since an
  external callee's entries are ALL named, this is satisfied by construction —
  but assert it, because a partially-resolved callee is exactly the bug shape.
- **A labelled pair carries `dst` 0 on the wire** (phase-1 ruling, carried in
  above): the wire gives that field to the label, so writing a resolved index
  back would break `from_bytes(to_bytes(x)) == x`. The IR's `IrMapDst::Label`
  must therefore serialize as a label and the object writer must put 0 in the
  index field. Verify against `crates/core/src/formats/object/write.rs` before
  relying on it.
- **Ordering.** `resolve_binding` today walks `callee.tapes` and finds each
  one's argument, so entries come out in the CALLEE's tape order. For an
  external callee the declarations table supplies that order. If the callee's
  declarations are NOT available (no `--extern`, no sibling, no library), the
  site keeps its source order and every entry is named — which is precisely
  what the linker's `reorder_named` exists for. **Both cases must be tested**,
  and the second is the one that makes "a bare `tmt compile` with no knowledge
  of any library still produces a linkable object" true.

**The emission branch** (replacing `ir.rs:735-741`):

```rust
    // An EXTERNAL callee's tape order, parameter names and glyph indices are
    // the linker's to resolve: the compiler emits a symbolic record — the
    // parameter's name where an in-unit site writes a position, the callee
    // glyph's label where it writes an index — and the link-time pre-pass
    // turns it back into the index-based binding the composition engine
    // consumes (docs/formats.md (bound calls)).
    //
    // `caller_tape` and `src` stay numeric in both forms: both name the
    // CALLER's own bands and alphabet, which this unit declares.
    if external {
        let callee_decl = decls.routine(target);
        let mut binding = Vec::with_capacity(named_args.len());
        // With declarations, entries go out in the callee's tape order and
        // every parameter is checked here; without them, source order and
        // named entries, which `reorder_named` fixes at link time.
        let order: Vec<&BindingArg> = match &callee_decl {
            Some(sig) => order_by_callee_tapes(sig, &named_args, site)?,
            None => named_args.clone(),
        };
        for arg in order {
            let BindingValue::Named { target: host_name, map, .. } = &arg.value else {
                unreachable!("named_args are Named by construction");
            };
            let (phys, host_tape) = host_tape_of(host, host_name, arg.name_span)?;
            let host_glyphs = &expanded.alphabets[&host_tape.alphabet].glyphs;
            let mut pairs = Vec::new();
            if let Some(m) = map {
                for p in &m.pairs {
                    // `src` resolves against the CALLER's alphabet, which is
                    // this unit's; `dst` travels as a label.
                    let src = glyph_index(host_glyphs, &p.src).ok_or(CompileError {
                        span: p.src.span(),
                        kind: CompileErrorKind::MapSymbolNotInAlphabet(glyph_label(&p.src)),
                    })?;
                    pairs.push(IrMapPair {
                        src: src as u32,
                        dst: IrMapDst::Label(glyph_label(&p.dst)),
                        one_way: p.arrow == MapArrow::ReadOnly,
                    });
                }
            }
            binding.push(IrTapeBinding {
                param: Some(arg.name.clone()),
                caller_tape: phys as u32,
                pairs,
            });
        }
        return Ok(binding);
    }
```

`host_tape_of` and `order_by_callee_tapes` are extracted from today's in-unit
loop so both paths share them — the in-unit branch keeps its behaviour exactly,
which is what the byte-identity gate below checks.

### Task 12: `noreturn`, and `unreachable-continuation`

**Requirements**

- **`noreturn` is a fact of the body, exported as a clause.** Whether a routine
  can return is: any `return` transition, any `then return`, or a graft exit
  bound to `return` in the expanded world — **counted conservatively, dead
  states included, so the fact is independent of `-O`**. That last clause is
  the important one and is easy to get wrong: computing it after the optimizer
  would make an object's interface depend on its opt level.

> The header's `noreturn` is checked at the site where a lie becomes

## Behaviour changes in phase 3a

*Written by Task 17, against the landed branch and the measured numbers. The
prose is what a release note can quote.*

**One. Every compiled object now describes its interface.** A `.tmo` built by
`tmt compile` or `tmt build` carries parameter names, per-tape glyph lists,
`writes` contracts and exported alphabets where it carried only arities and
cardinalities. Three consequences:

- The object grows, and `tmt dis` prints `.param` lines and `; alphabet`
  comments it did not print before. The CODE is byte-identical; Task 3 asserts
  that separately, because "the object was supposed to change" is otherwise a
  place a codegen regression can hide. Measured on the embedded standard
  library, end to end across the phase: **-O0 6103 → 7825 B, -O1 6043 →
  7765 B** (Task 3's interface section took it to 7243/7183; Task 13's graft
  digests and their string table added the rest). Task 17 re-measured the
  final figures with `stdlib_golden.rs::stdlib_object_sizes_are_reported`.
- An uncontracted tape publishes the compiler's own INFERRED write set rather
  than nothing, so "no clause declared" never reaches the wire as "may write
  anything". The entry world is the one exception — a `machine` is never a
  callee, so its `.param` lines carry glyph lists only.
- **The glyph-level link checks phase 2 landed become live.** A call site
  binding by index into a callee whose alphabet is the same size but spells
  different glyphs is now the warning `glyph-mismatch`; a narrower callee
  alphabet is `narrow-alphabet`; a wider one was already the error `CalleeWider`.
  Measured over the shipped corpus at Task 3 (the `plain_site_sweep`
  instrument plus `tmt build -v` over `docs/examples/tmt.json`'s six targets):
  **zero occurrences of any of the three**, before or after the change —
  `rpn.tmc`'s four plain call sites are the only graded ones in the corpus,
  and `bin` is position-identical to `std::binaryNumbers::symbols`. But **a
  user program that re-declared a stdlib alphabet in a different order has
  been silently re-labelling symbols and now says so.** That is the hazard the
  arc exists to close, and it arrives as a warning precisely so that working
  programs keep building. `with map { }` — a written empty map — is the
  deliberate opt-out at a site where the re-labelling is the intent.

**Two. Two error codes are retired, because what they stood in for was built.**
`external-binding-unsupported` — a `call`/`bind` binding tapes into a routine
defined outside the unit — now compiles, emitting a symbolic site the linker
resolves. `state-param-continuation-unsupported` — a routine handing control to
its own `state` parameter — now lowers to `retx`. Programs that previously
failed to compile now compile.

**Two source shapes that used to compile now do not**, and both are language
0.2 acceptance changes rather than diagnostics: `noreturn` is the
twenty-eighth reserved word, so a 0.1 program using it as a name is now
`reserved-name`; and `main` is reserved for the entry world in EVERY unit, so
a library declaring a top-level `routine main` / `graph main` is now
`duplicate-name` (it was legal in a `machine`-less file before, and could
never have been linked beside any program). `TMC_LANG_VERSION` moves 0.1 →
0.2 for these, not for the additive grammar.

**Three. Declarations reach the compiler, and the diagnostics say so.**
`unresolved-alphabet`, `undefined-graph` and the new `undefined-map` each
distinguish "no such name" from "declared, but its declarations were not
given — declare it locally, or supply its declarations to this compile".
`graft-call-unsupported` keeps its code and drops "it awaits binding
composition" for actionable advice: write it as a routine, with `state`
parameters if it needs several exits. Those codes do not change; the texts do,
so a script matching on message text will see the difference. New codes:
`machine-in-declarations`, `routine-body-in-declarations`, `undefined-map`,
`map-not-closed`, `named-map-source-mismatch`, `named-map-target-mismatch`,
`too-many-state-params`, `state-args-need-declarations`, `noreturn-violated`,
`then-required`.

**Four. New surfaces.** `tmt interface INPUT [-o OUT.tmh]` is a fifteenth
subcommand, and it takes `--extern`/`--nostdlib` itself on a text input (a
usage error on an object, which has nothing left to resolve). `tmt compile`
gains `--extern FILE` (repeatable) and `--nostdlib`. `tmt build` takes NO
`--extern` — it derives declarations from sibling sources and from libraries,
through a fixpoint, with no manifest key of its own — and honours `stdlib:
false` at the compile stage as well as the link stage; **that last one is a
behaviour change to an existing manifest setting**, and a project relying on
`stdlib: false` to affect only linking will see `std::` names become external
at compile time too. `tmt build`'s `-L`/`-l` now feed compile-time
declarations as well as the link; `tmt link`'s `-l` still does not, and still
cannot use a header-only library.

**Five. Three new lints, all default-on.** `duplicate-graft-instance`,
`unreachable-continuation` and `unused-map`. `dead-map-pair` extends to named
maps. A `tmt lint` that was clean can now report; `--allow` and `lint.allow`
suppress them through the namespace that already exists.

**Six. One new link warning.** `tail-call-no-continuation`: a call into a
callee that can return, where the call is either the last instruction of its
function or is immediately followed by the dialect's own trap — the shape the
compiler emits for a call written without `then`, whatever code follows that
trap. It fires on the hand-written `.tma` equivalents too, and it is how a
header that LIES about `noreturn` is caught: the callee "can return" by its
interface bit OR by a body scan, so the linked body has the last word. A
`call` an author followed by a deliberate trap for some other reason reads the
same way and warns — the accepted false positive `--allow` silences. Warning,
not error, consistent across all three mechanisms and promotable by `-Werror`.
PM-1 links never run the check: no routine signatures, nothing to grade.

**Six-and-a-half. A new lint reaches the graft expander's own dedup.**
`duplicate-graft-instance` is keyed exactly as the expander keys a graft site
(target graph by owning unit and name, the tape composite, the continuation —
never the `as` name), so it reports what the compiler already treats as one
splice. Its quickfix is withheld on three shapes: the duplicate carries
`entry`, the removed name is referenced by anything other than a bare `goto`,
or the surviving instance is an anonymous `entry graft`.

**Seven. A glyph literal in assembly is now any non-empty content, as it
already was in source.** `docs/tmt/language.md` has always defined a `.tmc`
glyph literal's content as any non-empty UTF-8 string, so `'ab'`, `'->'` and a
multi-scalar cluster are ordinary glyphs; the `.tma` lexer accepted only one
character. Nothing collided while the compiler emitted no `.param`. Rather than
let interface emission produce disassembly the assembler refuses, the two
lexers are brought to one rule. A `..` range endpoint must still be a single
character or a bare number, unchanged. **The text-expressibility caveat list
loses its "multi-character label" bullet**, leaving three: `-g` debug
side-tables; exported and imported alphabets; and an object with grafts but no
interface. `CLAUDE.md` and `docs/formats.md` are made to name that same three —
they disagreed with each other before this phase, behind a matching count.
`pmt` is unaffected: the glyph literal rides the interface capability, which
PM-1 does not enable.

**Eight. A `.tmh` given to `tmt lint` or `tmt fmt` is refused by extension.**
Both print `error: unknown source extension (expected .tmc or .tma)` and exit
1 — today's behaviour, unchanged and deliberately so: linting and formatting
headers need a per-rule "applies to headers" flag and its drift guard, and they
land in phase 4 with `.tmh`'s editor and LSP routing. A header is *produced* by
`tmt interface` and *consumed* by `compile --extern` and `build` in 3a; it is
not yet a file the other tools open.

**Nine. Library graphs cross the unit boundary, and the link verifies the
splice.** A graph declared by a header grafts exactly like a local one, with
every name in the spliced body resolving in the DECLARING unit — a same-named
consumer alphabet is a different alphabet, and an identity graft between them
is `identity-glyph-mismatch`. Both sides record a CRC-32 of the graph's
canonical signature and body as the header printer renders them (doc lines,
comments, whitespace and unrelated declarations never move it) and the linker
refuses a drifted pair (`GraftDrift`); an imported alphabet is checked the
same way (`AlphabetDrift`). A header-only library is not checked — the one
place a header is trusted outright. A graft cycle through declared graphs is
`graft-cycle`. Known limitation, recorded rather than fixed: a diagnostic
about a declaration read from a header is rendered against the primary
input's path with the header's line:col.

**Ten. Version spaces that moved.** `.tmc` language 0.1 → **0.2**; TM IR 3 →
**4** (glyph tables, declared contracts, exits, the `returns` bit, symbolic
binding entries); TM-1 `.tma` dialect 0.4 → **0.5**, for the widened glyph
literal — additive, and a bump rather than a fold-in because 0.4 had already
shipped, which is the rule `docs/tmt/asm.md`'s own history section argues
from. All three are reflected in `CLAUDE.md`'s version table.

**Eleven. One defect the phase introduced, found in review and fixed.** An
import whose only use was a named map — a `with map NAME` argument at a
`call`, `bind` or `graft` site, or a `map NAME: SRC -> DST` declaration's own
alphabet references — was reported `unused-import` on both surfaces that read
one detection, and `-Werror` failed the build of a program whose import was
load-bearing. `mark_reference_imports` predated named maps and walked only
reuse TARGETS and signature alphabets; it now walks binding arguments' maps
and the map declarations too.

**What does not change.** PM-1 byte identity, core neutrality, `-O0` bit
identity, the `brk` barrier, the everything-matrix, the three-mechanism matrix,
`mode_equivalence`'s relink byte identity, and the derivation-first stdlib
goldens. The crate version stays 0.5.x; the `tmt.json` `project` schema stays
0.2; `pmt` is untouched end to end. (`TM1_TMA_DIALECT_VERSION` was the one
version space left behind — Task 17 reported it rather than moving a constant
its brief froze, and the fix round bumped it; see item Ten.)

## Decisions for the controller

Every point where this plan had to choose. None is settled by the spec.

- **(D1) RULED BY THE CONTROLLER, 2026-09-16: make it spellable. Task 2b.**
  This plan originally proposed declaring a fourth text-expressibility
  exception and recommended against widening the `.tma` glyph literal. **That
  recommendation was overruled, and the override is right on three grounds the
  plan had underweighted:**
  1. **It is not an emoji corner case.** `docs/tmt/language.md:72-76` already
     defines a `.tmc` glyph literal's content as *any non-empty UTF-8 string*,
     so `'ab'` and `'->'` are ordinary legal glyphs in a user alphabet — and
     they compile today (log row H1). The plan's ZWJ probe found a symptom and
     framed it as the disease.
  2. **The failure class is worse than the gate tolerates.** The two existing
     exceptions degrade by dropping data — an exported alphabet prints as a
     comment and reassembling omits it, but the output is still valid assembly.
     A multi-character label makes `tmt dis` emit a `.param` line the assembler
     REFUSES. "Lossy" and "invalid" are not the same concession.
  3. **The notation, not the format, is the outlier.** Core's own
     `parse_glyph_list` already accepts `'ab','c'` and already rejects
     `'ab'..'z'`, pinned in both directions by
     `crates/turing-machine/tests/glyph_notation_parity.rs` (verified green,
     log row H3) — and `docs/formats.md:698-701` says a `.param`'s `(…)` group
     IS that notation. So the `.tma` lexer contradicts the page defining the
     list it lexes. Widening it is a correction; declaring an exception would
     have carved the contradiction into the durable pages.

  Consequences, all owned by Task 2b except the last: the pinned core test
  flips to an acceptance test; a `'ab'` round trip through `.param` is added;
  the range endpoint stays single-character with its own test (the `.tmc` and
  `parse_glyph_list` halves are already pinned, so this is the third leg);
  the "single character" paragraph of `docs/formats.md` (glyph literals and
  glyph lists) is rewritten and the multi-character-label caveat bullet is
  **deleted**, leaving three caveats — `-g` side-tables, exported and imported
  alphabets, and an object with grafts but no interface; and **Task 17 checks
  `CLAUDE.md:213` names that same three**, which it does not today (it keeps
  the right digit while listing a different set).
- **(D2) IR v4 carries three things the spec does not name.** The spec lists
  `ReturnExit`, `CallThen.exits`, `IrTapeBinding.param` and the index-or-label
  `dst`. But `.param` needs glyph labels and `writes` sets, and `.routine` needs
  the exit count and the `returns` bit — and `codegen::emit_program`'s only
  input is `IrProgram` (Established fact 4). So `IrTape.glyphs`, `IrTape.writes`,
  `IrWorld.exits` and `IrWorld.returns` are additions the spec implies rather
  than states. **The alternative — giving codegen a second input — is worse**:
  it would make the IR no longer a complete description of what is emitted,
  which is the property that makes `tmt ir` a documented artifact.
- **(D3) ACCEPTED by the controller, 2026-09-16: `tmt lint` and `tmt fmt` on a
  `.tmh` are phase 4.** `fmt` is nearly free off the green tree, but `lint`
  needs the per-rule "applies to headers" flag **and its drift guard** — a
  whole surface — and R-3a-4 already puts LSP routing of `.tmh` in phase 4.
  Splitting `fmt` out would ship a `.tmh` surface that formats but cannot be
  linted or opened. **No new code in 3a**: both subcommands already refuse a
  `.tmh` by extension, cleanly and by name — verified,
  `tmt lint mylib.tmh` and `tmt fmt mylib.tmh` each exit 1 with
  `mylib.tmh: error: unknown source extension (expected .tmc or .tma)`
  (log rows I1–I2). Stated in Behaviour changes so a user who generates a
  header and reflexively formats it is not surprised.
- **(D4) `unused-map` and the `dead-map-pair` extension ride with named maps
  (Task 9), which widens the spec's "the two new lints" line.** The Disposition
  names "the two lints" alongside named maps, and those two are
  `duplicate-graft-instance` and `unreachable-continuation` — but a named map
  nothing uses is a 3a-only surface, created by 3a, and shipping the feature
  without its hygiene rule would leave a gap only phase 4 could close.
  **Deliberate widening, disclosed.** Defer both if the controller prefers the
  line read literally; Task 9 stays otherwise intact.
- **(D5) ACCEPTED, and Task 16 is TAKEN (controller, 2026-09-16).** It keeps a
  PULLABLE mark only as a note that pulling it would change nothing else.
  Core neutrality says a core diff in a compiler phase is a design smell; this
  phase justifies **two**, in the same terms. Task 16: the check is
  arch-agnostic (a blob length, a site address, a `returns` bit), it reuses a
  predicate phase 2 already wrote and pinned, it discharges two carries at
  once, and it is tested on the crate-private fake dialect. **Task 2b**: a
  lexer rule in the shared asm layer, under a capability PM-1 does not enable,
  bringing the notation into line with the glyph list `docs/formats.md` says
  a `.param` already uses. Both are the shared layer catching up with what the
  object format stores, not core learning anything about an architecture.
- **(S3 restated, because it is the plan's own finding)** The brief asks how
  the header check and phase 2's `callee_can_return` body scan relate. They are
  the same check, seen from two ends. A compiler-produced header and its
  object's `returns` bit come from one inferred fact (Task 12), so they cannot
  disagree; headers reach the linker not at all (P9); and the one observable
  consequence of a lie is a site with no continuation into a callee that
  returns — the predicate `check_splice_site` already computes. **There is
  nothing left to compare, and adding a record-vs-record check would be
  ceremony.** Stated so a reviewer sees it was decided, not skipped.
- **(Two codes, not four)** Both the `unresolved-alphabet` and the
  `undefined-graph` splits keep ONE code and widen to two message texts. The
  alternative — a code per case — would move `error_code_docs.rs`'s set and add
  two names to the shared allow namespace for no gain, since neither case is
  separately suppressible (both are errors). **If the controller wants them
  separately greppable, say so before Task 8.**
- **(Reserved-word arithmetic)** The spec's #121 section says "reserved words
  27 → 30 (`enters`, `leaves`, `set`)", which omits `noreturn` from the main
  section. 3a takes 27 → 28; 3b takes 28 → 31. **A spec arithmetic slip, not a
  plan deviation**, recorded so 3b's plan does not inherit it.
- **(Ordering) `--extern` files first, embedded stdlib last.** So a user's
  `std` shadows the built-in one. This mirrors the linker's first-wins rule
  deliberately: a compiler resolving a name differently from the linker would
  diagnose a program the linker then builds differently. **The alternative —
  the built-in stdlib always first — makes `--nostdlib --extern my_std.tmh` the
  only way to override, which is a worse ergonomic for no safety gain.**
- **(Conservatism) An exit-bearing callee is not inlined in 3a** (Task 11).
  Inlining one is sound only if the site's exits replace the callee's
  `ReturnExit`s — that is the multi-exit fold, and it is phase 4's `outline`
  work. Refusing is correct and costs an optimization on a construct that did
  not exist yesterday. **Pinned by a test so it is a decision, not a drift.**
- **(Conservatism) Task 3 does not emit `exits=` or `noreturn`.** Both are
  suffixes for non-default values, and until Tasks 11 and 12 every world has
  zero exits and returns. Emitting them anyway would break the writer's
  "lowest version that carries the content" rule and move every object for
  nothing.
- **(Measurement) Task 3's sweep has a STOP gate, not a fix instruction.** If a
  shipped example trips `glyph-mismatch` or `narrow-alphabet`, the implementer
  reports rather than edits the example: a shipped program that was silently
  re-labelling symbols is a finding about the corpus. Established fact 3 says
  none should. Phase 2's ruling 27 is the precedent for how such a finding is
  handled (the controller decided; the implementer did not).
- **(Task 1 cost) The stdlib's `Resolved` is CLONED per compile.** It is
  `&'static` today and free. The clone is what removes the `'static` constraint
  that blocks headers, and one type for both cases is worth it. **If a later
  task reports a compile-time regression, the alternative is a `Cow`-shaped
  `Declarations` — but do not build that speculatively**; the phase-2 ledger's
  measurement says `expand`, not resolution, dominates.
