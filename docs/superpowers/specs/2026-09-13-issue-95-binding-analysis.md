# Issue #95 — the `.tmc` binding mechanism: analysis outcome and the change

Draft of the closing comment for https://github.com/mellonis/machine-toolchains/issues/95, folding in #118. Internal artifact: forge links and tracker numbers are fine here. Everything below was checked against master (`2c36ebd`); citations are `file:line` on that revision. Every decision here was ratified item by item on 2026-09-13.

## Analysis outcome

Verdict per item, the answer to the framing question ("does the stdlib ship as source on purpose?"), and a full change description for the one design that falls out — because items 1, 2 and 4, the `state-param-continuation-unsupported` limit, and #118's parked form C all turn out to want the same additions to the object format, the linker and the front end.

### Summary

| Item | Verdict | One line |
|---|---|---|
| 1. Cross-unit binding | **liftable** | The linker already does everything; only the front end lacks the callee's parameter names and glyphs. Declarations reach it through headers, never through objects. |
| 2. `graft` across a link boundary | **splice through an object: inherent. Graft of a library graph: liftable through headers** | Objects carry no graphs and the linker cannot splice N-exit bodies. But a graph *is* source, and a `.tmh` header carries `export graph` bodies whole, so a library graph is grafted at compile time exactly like an in-unit one. Multi-exit *calls* come from routines gaining `state` parameters (#118's form C). |
| 3. `call` inside a grafted graph | **not worth lifting** | The compile-time splice of a call-bearing graph needs a map-composition operation the compiler lacks, for a gain measured in a few trap rows; a routine with `state` parameters expresses the same behaviour and is callable everywhere. |
| 4. Index identity is unchecked | **hazard confirmed, worse than stated** | The lint cannot fire on the cross-unit case at all, and the linker checks nothing on a plain call site, not even cardinality. Demonstrated on master; item 1's interface section fixes it. |
| 5a. `callee_arity ≤ caller_arity` | **keep as is** | The real limit is the image's fixed band count, not injectivity; the corpus threads a scratch tape from the caller and that documents it better. |
| 5b. Pre-bound graft | **nothing to add; a hygiene lint instead** | Two splices with one argument list are indistinguishable from one named instance, and the expander already dedups them. A `duplicate-graft-instance` lint tells the author. |
| 5c. Partial binding | **not now; path open** | "Omitted" in the issue text is the `with map`, never an argument; `bind` stays fully bound. Named maps remove the main reason to want it. |
| 5d. LSP narrowness | **consequence** | The overlay reads the same declarations the compiler does, so it widens exactly as far as the compiler does, and it also shows the linker's plain-site checks best-effort. |

### "The stdlib ships as source" — half right, and the wrong half was the problem

All three consumers (CLI, LSP, wasm) link the compiled object: `crates/turing-machine/src/stdlib/mod.rs:57` (`OnceLock`, `-O1`, stripped), `cli/driver.rs:469`/`:716`, `crates/wasm/src/inner/stdlib.rs:31`. There is **no build mode** in which "the library's source is compiled into the consumer's own unit" — no flag, no manifest key, no `use` form. The sentence in `docs/tmt/stdlib.md:85-88` describes a precondition a user can only satisfy by pasting `std.tmc` into their file, and doing so silently shadows the linked library (`crates/core/src/linker/resolve.rs:246-262`, first-wins, shadowed copies unreported).

The phrase conflates two restrictions:

- `graft std::…Graph(…)` needs the graph's *source*. True and permanent for objects — and the right consequence is that graphs travel as source, in a header, on purpose (item 2).
- `call std::…(num = t)` needs the callee's *interface*. Not a ruling: `external-binding-unsupported` was born in `1fb248a` as the fix for an `.expect` panic in `resolve_binding`, sits under `// -- IR-lowering scope limits (composition engine not yet online)` (`compiler.rs:270`), and `docs/tmt/stdlib.md:81` already calls it "a limit it has not lifted yet, not a property of the language". The engine has long been online; the comment is stale.

**Ruling:** the graph half becomes deliberate — `std.tmh` ships the graphs as source; the binding half is a symptom removed by item 1. After the change the stdlib is consumed from its object plus its header in every form the language offers, and the `std.tmc` header comment is rewritten accordingly.

### Item 1 — cross-unit binding: liftable, the barrier is entirely in the front end

**What the linker already does.** A bound-call record is fully index-based (`docs/formats.md`, bound calls; `crates/core/src/formats/object.rs:151-175`). `resolve_target` is shared by relocations and bound calls and resolves through the global namespace, user objects **and** libraries alike (`crates/core/src/linker/resolve.rs:305-312`, bound-call loop `:368-386`). `binding_to_composite` validates arity, caller-tape range, injective placement, symbol ranges and the blank pin from `RoutineSig` alone (`crates/core/src/linker/compose.rs:288-360`). There is no "is this callee external?" check anywhere in the linker; by then the concept does not exist.

**What the compiler lacks.** `resolve_binding` (`crates/turing-machine/src/ir.rs:709-800`) reads two things off the callee's `ExpandedWorld`: parameter **names** (`:751`, to order the binding by the callee's tape order) and per-tape ordered **glyph labels** (`:780-798`, to turn `'0'` into a `dst` index). Neither exists in an MO object; `RoutineSig` is arity + cardinalities (`object.rs:129-135`). It needs nothing else — not the callee's states, rules or tables.

**Design.** Three pieces.

- *The object describes its interface* — a flag-gated section in MO v4: per routine its parameter names, ordered glyphs per tape, `writes` contracts and exit count; per object its exported alphabets. Not a compiler option: the compiler always has the data and always writes it, exactly like `.routine` signatures today. The gate bit spells "this object does not describe its interface" as a typed state — pre-v4 objects, PM-1 objects (nothing to describe) and a hand-written `.tma` that omits the fields all read the same way, the writer keeps choosing the lowest version that carries the content, and PM-1 output stays byte-identical.
- *Names and glyphs resolve to indices in the linker.* The compiler emits a *symbolic* bound-site record — parameter name instead of list position, glyph label instead of `dst` index — and the linker resolves it against the callee's interface section and hands the composition engine the same index-based binding it consumes today. Consistent with what the language already does: binding legality for `call`/`bind` is enforced only by the linker (`docs/tmt/language.md`, symbol maps). A bare `tmt compile` with no knowledge of any library still produces a linkable object; `missing-arg`/`unknown-arg` for an external callee are then link errors (function + offset, plus a source line under `-g`). The `.tma` binding operand gains a symbolic spelling so the text-expressibility gate holds.
- *Declarations reach the compiler as source, never as objects.* What the compiler needs before link is declarations: alphabets with glyphs, routine signatures, named maps, and graph bodies (item 2). They are source-level, so they travel as source. A **`.tmh` header** is the `.tmc` grammar read in declarations-only mode: `export alphabet`, `export map`, `export routine`/`export graph` signatures with contracts and `?` doc lines, and — because a graph has no other form — `export graph` bodies in full; routine bodies are dropped. `tmt compile --extern FILE` (repeatable) takes a `.tmh`, or a `.tmc` read the same way, so a header-only library needs no generation step. `tmt build` hands each unit the declarations of its sibling sources and, for each library on the `-L` path, whatever exists of `<name>.tmo` (its interface section) and `<name>.tmh` (graphs, maps, docs); either may be absent, both absent is an error. A graphs-only library is header-only: its object is empty (verified: 27 bytes) and is never linked. The one compile-time cross-unit mechanism the compiler already has, `ExternalContracts::Stdlib` (`compiler.rs:2115-2129`), which reads the stdlib's *source* for `writes` contracts, generalizes into this; the LSP overlay already parses sibling sources for their exports (`lsp/overlay.rs:331-371`) the same way.

**Headers carry no authority.** Because emitted bound sites are symbolic and the object carries the real interface, the linker re-resolves every parameter name, glyph and imported alphabet a header supplied; a header that drifted from its object is a link error. Graph bodies have no object counterpart to resolve against, so they are verified by **digest**: the library object's interface section records, per exported graph, a CRC-32 of the graph's canonical header text (the rendering `tmt interface` prints, so whitespace and comments cannot perturb it); the consumer's object records, per library graph it grafted, the graph's qualified name and the digest of the body it actually spliced; the linker compares the two whenever the library's object is in the link, and a mismatch is the error "`lib::findAGraph` was grafted from a header that does not match `lib.tmo`". A header-only library has no object and therefore no check — the one place a header is trusted, stated as such. Named maps expand into pairs the linker resolves by label, so they need no digest. Headers are generated by `tmt interface`, never hand-edited, and `std.tmh` is pinned.

**`tmt interface INPUT [-o OUT.tmh]`** — a fifteenth subcommand. `INPUT` is a `.tmc` or a `.tmo`, told apart by `sniff()` on the container magic, never by extension (the `tape-block new --from APP.tmx | APP.tmc` precedent). From source the header is complete; from an object it carries routine signatures, contracts and exported alphabets but no graphs, maps or doc lines, which is the one difference worth stating in `--help`.

**The stdlib ships `std.tmh`**, embedded next to `std.tmc`, read implicitly the way the stdlib object is linked implicitly, and pinned by a test to `tmt interface std.tmc` byte for byte. It is the carrier of the stdlib's graphs and named maps, a shipped example of a header, and a standing proof of the generator. `std.tmc` keeps compiling the object and being materialized by the LSP for navigation into bodies. **`--nostdlib` reaches `compile`**: it skips the embedded header, `std::…` names become external like any other, the manifest's `stdlib: false` now covers both stages (`build` passes it to compile and link), and an explicit `--extern std.tmh` still works — a user may disable the stdlib and provide their own library under `std`.

**Alphabets are importable, and a qualified name is accepted wherever an alphabet is referenced.** `use lib::bits;` already parses today and fails only at `tape t: bits;` with `unresolved-alphabet`; with the library's declarations given, it resolves. `tape num: std::binaryNumbersBare::symbols;` and `routine r(tape t: lib::sym)` become legal — today both positions parse only a bare name (verified: `expected ';', found '::'` and `expected ',' or ')', found '::'`), an asymmetry with `call`/`graft`/`bind` targets, which take qualified names without `use`. `unresolved-alphabet` tells "no such alphabet" apart from "declared by `use`, but its declarations were not given — pass `--extern` or declare it locally".

**Named symbol maps.** A map declared once, typed by its two alphabets, exportable and importable like an alphabet, used by name:

```
map wideToBits: wide -> bits { '^' => '_', '$' => '_', '0' -> '0', '1' -> '1' }

bind plusOne(num = data with map wideToBits) as inc;
[*] -> call invert(num = data with map wideToBits) then t;
```

The compiler checks the declaration once (pairs belong to the named alphabets, blank pinned, injective on equal cardinalities, closed on unequal) and at each site only that the caller tape's alphabet is the map's source and the callee parameter's alphabet its target. The inline form stays, `with map { }` included. Maps go into `.tmh`; the linker never sees them (a use expands to the same pairs, symbolic for external callees). The stdlib exports its canonical cross-representation maps instead of writing the delimited→bare collapse inline in `invertNumber`.

**Three equal ways to run a library routine over a tape, none mandatory:** import the library's alphabet (glyphs match by construction, nothing to check); keep a local alphabet and bind through an explicit map, inline or named (glyph-aware by construction, never warned on, and the only form across differing cardinalities); or keep a local alphabet and bind by index — a transparent call or an omitted map — where the linker warns on differing glyphs and `with map { }` says the re-labelling is meant (item 4).

### Item 2 — `graft` across a link boundary: the splice through an object is inherent; the graph travels as source instead

**The splice through an object.** `expand.rs` consumes the graph's parsed body, its alphabets as glyph vectors, its exits and its nested grafts (`expand.rs:1424-1447`, `:1032-1078`); the output erases graphs (`:49-51`). `crates/core/src/formats/` has no graph, exit or template record; `SymbolDef` is `Defined | Local | External` over code blobs (`object.rs:102-114`). The linker's one code-multiplying mechanism, mono stamping, produces a callable entered by `call` and left by `ret` (`stamp.rs:4-8`); a graft wires N named exits into the middle of a host function. Shipping graph IR in the object and running the expander inside the linker would be relocating a compiler phase, and nothing motivates it. **The linker and the object format learn nothing about graphs.**

**The graph travels as source.** A graph is a compile-time template; its only form is its source, so its distribution form is source too: `export graph` bodies go into `.tmh` whole, and a consumer given the header grafts a library graph exactly as an in-unit one — same splice, same private copy per site, same glyph identity, same `expand.rs`. `export graph` therefore has a purpose (it is what enters the header), `graft` keeps meaning exactly "compile-time splice", and `undefined-graph` now tells "no such graph" apart from "the graph is in a unit whose declarations were not given". The splice is verified after the fact: the library object carries a digest of each exported graph's canonical text, the consumer records the digest of what it spliced, and the linker refuses a mismatch (P9). A graph is never callable; `call` on a graph stays `wrong-target-kind`.

**Multi-exit calls come from routines.** What a graft buys beyond a splice — several static continuations — becomes available across a call boundary through **`state` parameters on routines**: `goto k` on a parameter compiles to `retx #k`, the call site passes `state` arguments, and they become the site's exit vector. The ISA already carries the mechanism: `retx #k` leaves the active frame through exit `k` of its exit vector (`docs/tmt/isa.md`, multi-exit returns), and in the VM it is a paired pop identical to `ret`'s — the return address is popped and discarded, the caller's FR is popped and restored, the descriptor reloads when non-identity, control lands on exit `k` (`crates/core/src/vm/core.rs:770-785`, `:552-561`; pinned by `framed_call_activates_translates_and_retx_exits`). Today it is reachable only from hand-written `.tma` through a raw `.frame`/`.exits`, and only under `--call-mech=frames`. Three links are missing above the assembler: the compiler never emits `retx` — a routine handing control to a `state` parameter fails with `state-param-continuation-unsupported` (`ir.rs:612`); a declarative bound call carries no exit vector (`engine.rs:685`); mono refuses raw frames (`MonoRawFrame`) and so never stamps exits.

**#118 examined precisely this and parked it** — as an `outline` optimization, measured at half a percent of one image. Two of its findings carry over unchanged: a raw `.frame` inside a routine world is unsound (it bypasses `compose[FR][site]`), and the hybrid condition is a property of the link. Its form C — a declarative bound call carrying an exit vector, lowered per mechanism, frames through compose and mono by "un-outlining" into per-occurrence copies — is the only sound shape, and it now has two consumers instead of one: routines with `state` parameters, and #118's multi-exit fold. The cost is paid once; the justification no longer rests on `outline`.

**A consumer chooses the form.** A library ships a graph, and optionally a routine facade that grafts it — `export routine findOne(tape t: bits, state hit, state miss) { entry graft findOneGraph(t = t, hit = hit, miss = miss); }` — so consumers can share one standard body instead of splicing copies. The consumer may graft the graph at every site and rely on `outline` to fold repeats, call the library facade, or write their own routine. The stdlib keeps its graph + facade pairs; nothing is renamed.

### Item 3 — `call` inside a grafted graph: not worth lifting

**Why the splice fails today.** The guard is at `expand.rs:1296-1308`; its message says "awaits binding composition" (`compiler.rs:638-643`). A splice copies the graph's states into the host and rewrites their rows through the graft site's composite; that works because a row is data. A `call` inside the graph carries a *symbolic* binding — `BindingArg`s naming the graph's own tapes and glyphs (`expand.rs:136-143`) — and after the splice those tapes no longer exist. Take a graph that composes three routines over a `bits` tape, grafted into a `wide` machine through a map:

```
export graph minusOne(tape num: bits, state done) {
  entry state a { [*] -> call invert(num = num)  then b; }
  state b       { [*] -> call plusOne(num = num) then c; }
  state c       { [*] -> call invert(num = num)  then done; }
}

machine {
  tape data: wide;
  entry graft minusOne(num = data with map { '0'->'0', '1'->'1' }, done = stop);
}
```

To keep the inner call correct, the compiler would have to write `call invert(num = data with map { … })` in the spliced copy — the graft's `wide → bits` map composed with the call's own `bits → bits` binding. The compiler-side map algebra has `SymMap::apply`, `TapeMap::read_image`, `write_image` (`expand.rs:184`, `:224`, `:232`) but **no `compose`**; only the linker has `compose_map`/`compose_composites` (`compose.rs:479-500`). And a composed binding with holes and one-way pairs is not always expressible as one `with map` — a composite is closed under composition, a binding is not. That is the whole of the 0.1 limit, and why the stdlib's `minusOne` is a routine with no graph form. Headers change nothing here: a library graph with a call inside hits the same guard when grafted from `.tmh`.

**What expresses the same behaviour.** A routine with `state` parameters. Its inner calls are transparent — inside the routine `num = num` is the identity on its own tape — so nothing is composed at compile time; the linker composes at the call site with what it has: under frames a transparent call inside the body **inherits the active frame** (`invert` reads and writes through the caller's descriptor, FR unchanged, as any bound routine with transparent calls inside runs today); under mono `mono_stamps` stamps the routine and, recursively, its **closure** under the same composite. So `minusOne` stays a routine, callable from any unit with a map, and the guard's message becomes actionable: "`minusOne` contains a call; a call-bearing graph is not spliced — write it as a routine, with `state` parameters if it needs several exits". The compiler-side `compose` is not built.

**What a splice would have given** — a comparison, not a regression, since today a call-bearing graph can be neither grafted nor called across a map. A splice puts the graph's states into the host world, where the per-world `-O1` passes see them: `dead-rows` would drop the rows under the map's holes at compile time, and a `done = stop` terminator would land directly in state `c`'s row. Across a call boundary those do not happen: under mono the linker synthesizes trap rows for the holes instead, and the body ends in `ret` with the `stp` one instruction later in the host. Inside the routine, optimization is complete — `inline` splices `invert` and `plusOne` into `minusOne`'s body at `-O1`, since a bindless call to a small leaf is its standard case. The price is a few trap rows and an unmerged tail in the narrow case "non-identity map, call-bearing body". Not worth a second map algebra.

The earlier sketch — `compose` on `SymMap`/`TapeMap`/`Composite`, the remap closure extended to `Call`/`BindCall`, `resolve_binding` accepting pre-composed bindings, the footprint-engine, dedup-key and `GraftCycle` risks (`footprint.rs:731-733`, `expand.rs:264-276`, `:1117-1150`) — is recorded here so it is not re-derived if an optimizable splice of a call-bearing graph is ever actually needed.

### Item 4 — index identity: confirmed, and worse than the issue states

- **The lint cannot fire on this hazard.** `index-identity-map` inspects only `Named { map: None }` binding args (`lint/rules/index_identity_map.rs:66-70`) — a transparent call has none — and skips `external: true` callees outright (`:114-118`, `:125-127`). It is opt-in (`--warn index-identity-map`), not warn-tier (`docs/tmt/lint.md:33-38`). The pointer in `docs/tmt/language.md:722-724` directs the reader to an audit tool that is silent by construction for the cross-unit case.
- **The linker checks nothing on a plain call site.** Signature comparison happens only on `SiteKind::Bound` (`engine.rs:562-574`); the `Plain` arm pushes the callee and moves on (`:578-583`). Not even arity or cardinality.
- **The normative rule is in the wrong page.** "Same glyphs in the same order" lives only in `docs/tmt/stdlib.md:70-76`; `language.md` never says an exported alphabet is unnameable across a unit.

Demonstrated on master, so the hazard is not hypothetical. Two programs differing in one line — `alphabet bits { '_', '0', '1' }` versus `{ '_', '1', '0' }` — each `call std::binaryNumbersBare::plusOne()` on the tape `011`. Both build, lint and run with exit 0. The first yields `100`; the second yields `010`, silently: the library reads the caller's `'1'` (index 1) as its own `'0'`, adds one to the number it sees, and the caller reads the result back through its own glyphs.

Mechanisms: (a) plain-site arity/cardinality check from `RoutineSig` — cheap, cannot catch reordering; (b) glyphs in the object — the only mechanism that detects reordering, and exactly item 1's interface section; the caller side of a transparent call is the entry world's own glyphs, since a transparent call runs on the machine's physical bands; (c) strict mode — policy, not detection; (d) user's contract — the status quo, defensible only after the docs pointer is fixed. **Verdict:** (b) via item 1, (a) as the degradation when the callee carries no interface, and alphabet import as the way to make the question not arise.

**The diagnostic is a warning, and the opt-out is local.** Index re-labelling is intended semantics by the language's own ruling, so a hard error would contradict the reference and break working programs on upgrade. But a warning that can only be silenced globally gets silenced globally, after which the accidental case is invisible again — so intent gets a spelling at the site: an explicit map is the glyph-aware statement and is never warned on; **the empty map `with map { }` — legal today, documented nowhere — gets the meaning "index identity, on purpose"**, silencing the check for that binding; a transparent argless call has no operand to carry intent, so an author who wants it silent locally writes the bound form `call std::…::plusOne(num = num with map { })`. A global `-Wno-`/manifest allow exists for legacy code as the last resort, and `-Werror` promotes for strict CI. The warning names the site, the two alphabets and the first differing position, and suggests `with map { }` when the re-labelling is meant.

**Sizes on a plain site are graded by whether the callee can touch what the caller lacks:** a callee wider in alphabet or in tape count is an **error** (it would write an index the tape cannot hold, or address a band that does not exist — the VM faults on the latter today, the former corrupts silently); a callee narrower in tape count is **silent** (a transparent call on the first `k` bands is how it is meant to work); a callee narrower in alphabet at equal tape count is a **warning**, like a reordering. The user sees these at `tmt link`/`tmt build`, and in the editor best-effort (5d).

**The lint stays as it is, opt-in and in-unit.** In-unit it gives a compile-time finding with an exact span where the linker can give only a function and an offset, and an in-unit author sees both alphabets in one file, so default-on would mostly flag deliberate re-labelling. Its description in `lint.md`, and the pointer in `language.md`, are reworded to say plainly that it covers the in-unit case and the linker covers the cross-unit one. The "same glyphs, same order" text moves into `language.md`'s symbol-map section as the description of what a transparent call does and what the linker checks, with importing the alphabet and mapping explicitly as the two alternatives to re-declaring by position; `stdlib.md` keeps the index table as the worked example.

### Item 5

- **5a — keep as is.** The constraint is not injectivity; it is that the image's band count is the entry function's arity (`linker/mod.rs:454-476`) and the VM's device count is fixed at load (`cli/run.rs:196`, `vm/machine.rs:206-235`). A wider callee would name a band that does not exist. Demand is real — `rpn.tmc:234` `mulInto(…, tape tmp: bin)`, `:252` `divInto(…)` — and is met by declaring the scratch band at the caller (`rpn.tmc:362`), which also documents what the band holds on return. Lifting it would mean the image's width as a maximum over reached routines plus a semantics for private bands; not wanted.
- **5b — nothing to add; a lint instead.** A named graft instance is a real subgraph of the host, and other states transition into it like into any state; "one argument list, several sites" in `bind`'s sense would mean several splices from one list, and those are indistinguishable — the list fixes tapes *and* exits. The expander already dedups them: `expand_grafts_into` keys an instance by graph, composite and continuation substitution, and a second identical site becomes an alias of the first (verified: two identical sites emit one subgraph, the second name disappears). So the program never bloats, at `-O0` too. What is missing is the hint: `tmt lint` says nothing about the redundant site. A **`duplicate-graft-instance`** lint, default-on, with a quickfix that removes the duplicate declaration and redirects its `goto`s, joins `unused-graft-name`; the key is the expander's, so there are no false positives.
- **5c — not now, path open.** Every parameter must be bound (`compiler.rs:2864-2874`), a `bind` target takes no call-site args (`bind-call-args`), and the issue's "omitted-map index identity" is about `with map`, not arguments. The one plausible shape — tapes fixed in a `bind`, exits chosen per site — was considered and is deliberately not built at this stage: it needs a second argument list on the call, a merge rule and a new `bind` semantics, for a saving that named maps mostly remove (the repeated part of a binding is the map, and that now has a name). Revisit with data if multi-exit routines over maps become common. `language.md` says so in one sentence under `call`.
- **5d — consequence, and the overlay follows.** The overlay excludes graphs (`lsp/overlay.rs:256-263`) and routes graft-target completion to the in-file roster (`lsp/complete.rs:214-269`) because each `.tmc` in a target is its own compilation unit (`cli/driver.rs:832-855`) and a sibling's graph was genuinely ungraftable. It already parses sibling sources whole and keeps only names (`overlay.rs:222-226`). With declarations flowing to the compiler, the overlay reads the same ones — sibling sources, `.tmh`, objects' interface sections, `std.tmh` — and widens exactly as far as the compiler does: graft targets from siblings and headers, parameter names and glyphs of external routines, alphabet and map imports, and the diagnostics the compiler raises on them. The seam where `external-binding-unsupported` was raised past `analyze_staged` (`overlay.rs:1264-1270`, green in the editor and red in `tmt build`) closes because the code is retired and the replacement checks run on the overlay's stage. The linker's plain-site checks of item 4 are shown best-effort too, since the overlay holds both alphabets; the link report stays the authority. `docs/lsp.md` states the principle: the editor shows what the compiler checks on declarations, mirrors the linker's site checks best-effort, and never pretends to be the linker for symbol resolution across a library chain or for mechanism and fold decisions.

## The change

One design covers items 1, 2 (headers and exits), 4, the `state-param-continuation-unsupported` limit, #118's form C, and the additions ratified along the way. Stated as soundness predicates first, then by layer.

### Predicates

- **P1 — exits go through compose.** A site's descriptor under frames is `compose(directory[FR], binding)` plus the site's exit vector. An exit-bearing call is sound in any world under any FR; the unsoundness #118 found belongs to raw `.frame`s that bypass compose.
- **P2 — mono enters through `jmp`.** TM-1 has no pop opcode, so `call` into a copy with `retx → jmp` would leak the return address. Under mono an exit-bearing site is lowered as `jmp` into a per-site copy in which `ret → jmp <then>` and `retx #k → jmp <exit_k>`. No stack interaction. This is a splice of the stamped body at link time.
- **P3 — an exit-bearing site never collapses to a plain call.** `is_full_passthrough` (`compose.rs:592-598`) gains the conjunct `exits.is_empty()`.
- **P4 — hybrid keeps its rule for exit-free sites and gains one for exit-bearing ones.** Exit-free: a bijection site is a mono seed, a holey site goes to frames (`stamp.rs:262-284`), as today. Exit-bearing: the bijection sites reaching one `(routine, composite)` are shared under frames — one body, one small descriptor per site, the multi-exit fold under hybrid — **when sharing pays in bytes**, and each is a mono seed (a per-site splice by P2) otherwise. "Pays" is computed, not configured: with `k` sites, a body of `B` bytes (its code blob plus its table blob) and descriptors of `d_i` bytes as the frames path would emit them, share iff `k ≥ 2` and `(k − 1)·B > Σ d_i + the compose-column entries`. So two sites over a 150-byte body share; two sites over a 12-byte one splice, because two copies cost less than a body plus two descriptor loads. The link report prints each decision (`k`, `B`, bytes saved) so it is auditable, and a `--hybrid-min-saving=<bytes>` knob can raise the bar later without changing the rule's shape. Holey exit-bearing sites go to frames as before. Everything here is a link-time count, deterministic, nothing predicted at compile time — which is what #118 asked of any hybrid arm. The count runs over the whole reachable set, not only the identity world: an exit-bearing site met while `mono_stamps` copies a routine under composite `C` joins its group, and when the group shares, the stamped copy carries a `call.m` to the shared body through a descriptor `compose(C, binding)` plus the site's exits — sound by P1, and the same mixed image hybrid already produces. So the fold happens wherever the sites are, including inside stamped closures.
- **P5 — injectivity and `callee_arity ≤ caller_arity` are unchanged.**
- **P6 — the "graft by glyph, call by index" split is untouched.** A graft, in-unit or from a header, is a compile-time splice with glyph identity checked by the compiler. A `call` with an omitted map binds by index, as the language rules; what the interface section adds is that the linker can now see when same-cardinality alphabets differ in glyphs, and it reports that as the same warning on a bound site with an omitted map as on a plain site (item 4). An explicit map, inline or named, the empty `with map { }` included, is the author's statement and is never warned on.
- **P7 — text-expressibility.** `.param`, the symbolic operand, the exits operand and `retx` are hand-writable, `tmt dis` prints them, dis → asm byte identity holds.
- **P8 — PM-1 byte identity.** Everything new sits behind flag bits and an `AsmCaps` capability PM-1 does not enable; the PM writer is untouched. PM-1 gets no header kind: `.pmc` functions have no parameters and no declared alphabets, so there is nothing a `.pmh` could carry.
- **P9 — headers carry no authority.** Everything the compiler takes from a `.tmh` about a routine or an alphabet is re-resolved by the linker against the object's interface section, because the emitted records are symbolic; a grafted library graph is verified by the digest of its body against the library object's record. The only trusted header is that of a header-only library, which has no object to check against. Headers are generated by `tmt interface`, and `std.tmh` is pinned.

### By layer

**Language `.tmc`, 0.1 → 0.2.** An external `call`/`bind` may bind tapes and carry `with map`; `external-binding-unsupported` is retired, its cases become link errors or compile errors when declarations are given. A routine may declare `state` parameters and hand control to them; `state-param-continuation-unsupported` is retired; a site writes `call r(t = x, k = next) then done`, where `then` is the `return` continuation and the `state` arguments are the exits. Whether a routine can return is a fact of its body — any `return` transition, `then return`, or a graft exit bound to `return` in the expanded world, counted conservatively (dead states included, so the fact is independent of `-O`) — and it is exported as a **`noreturn` clause** in the signature, in the style of `writes`: an author may write it and the compiler checks it against the body; `tmt interface` prints it from the inferred fact; one new reserved word. `then` is mandatory except when the callee is known as `noreturn`, where it may be omitted and, if written, is the lint `unreachable-continuation`; an unknown callee (no declarations given) keeps `then` mandatory, since the linker does not check it. `graft` keeps meaning "compile-time splice": a library graph is grafted from its header, and `undefined-graph` tells "no such graph" apart from "its declarations were not given"; `call` on a graph stays `wrong-target-kind`; `graft-call-unsupported` stays for a call-bearing graph, advising a routine with `state` parameters (item 3). An alphabet exported by another unit can be imported (`use lib::bits;`) and referenced when its declarations are given; `unresolved-alphabet` splits the same way. A qualified name is accepted wherever an alphabet is referenced. Named maps: `map NAME: SRC -> DST { pairs }`, exportable and importable, used as `with map NAME`; the inline form stays. The "same glyphs, same order" text moves into `language.md` as the description of what a transparent call does and what the linker checks, with importing the alphabet and mapping explicitly as the two alternatives to re-declaring by position. The empty map `with map { }` is documented for the first time, as "bind by index, deliberately": it keeps today's identity completion and additionally tells the linker not to warn about differing glyphs on that binding. One sentence each under `graft` (identical splices are one instance; the lint) and `call` (argument lists are complete; partial binding deliberately absent at this stage). A new file kind, **`.tmh`**, is the `.tmc` grammar read in declarations-only mode, versioned with the language.

**Compiler.** External declarations come from headers through the generalized `ExternalContracts` path (`--extern`, sibling sources and library interfaces from the driver, the embedded `std.tmh` unless `--nostdlib`): alphabet and map imports resolve against them, library graphs are grafted from them (each such graft recorded with the digest of the body spliced), bindings and contracts are checked against them early, and a `.tmh` or a `.tmc` is read in declarations-only mode by the same parser. TM IR 3 → 4: `IrTransition::ReturnExit { exit }` for `goto <state param>`; `CallThen` gains `exits: Vec<state id>`; `IrTapeBinding` gains `param: Option<String>`; a pair's `dst` is an index or a label. `resolve_binding` keeps today's index path for in-unit callees and emits the symbolic form for external ones (names, `dst` as labels, `src` and `caller_tape` as indices; an omitted map emits no pairs, per P6; a named map expands to its pairs). Codegen prints `.param`, the symbolic operand, the exits operand, `retx`. Every optimizer pass learns the new variants. `outline` gains the multi-exit fold from #118 — region key without junction ids, exits numbered by first appearance, trampoline = bound call with an identity binding and an exit vector — mode-independent because mono un-outlines by P2; stays default-off behind `--foutline`. The footprint engine changes only for the new variants.

**Assembler and `.tma`, TM-1 0.3 → 0.4, behind a new `AsmCaps` capability, PM off.** `.param <name>, (<glyphs>)[, writes=(<glyphs>)]` after `.routine`, once per tape, glyph count equal to the cardinality in `alpha`, glyphs in the core glyph-list notation; `.routine` gains `[, exits=<K>][, noreturn]` so the exit count and the `returns` bit are hand-writable too (text-expressibility, P7). Exported alphabets are the one interface datum with no directive — a compiler fact — and `tmt dis` prints them as `; alphabet <name>: (<glyphs>)` comments. Named binding operand `[num: 1{3->'0', 4->'1'}]`: parameter name on the left, `dst` an index or a quoted label, `src` always an index, no mixing of named and positional entries in one list. An exits operand on `call`, e.g. `call r [t: 1] exits=(next, giveUp)`, labels in the same function like `.exits`. Two object-level directives before the first `.func`, like `.volatile`: `.graph <name>, <digest>` declares an exported graph's digest, `.grafted <name>, <digest>` records a library graph the unit spliced — so the text-expressibility gate keeps its single `-g` exception. The disassembler prints all of them.

**Object format MO 3 → 4.** Interface section behind flags bit 5: per blob (parallel to blobs) `arity` parameter names via the string pool, per tape a glyph count and glyph strings and a `writes` glyph set, plus the exit count and a `returns` bit; and per object a list of exported alphabets, each a qualified name and its glyph strings, for `tmt interface` and for the linker's alphabet-import check, plus a list of exported graphs, each a qualified name and the CRC-32 of its canonical header text. A new **graft-provenance** list, unconditional with a count like bound calls: per library graph the unit grafted, the graph's qualified name (string index) and the digest of the body spliced. The bound-call record becomes a bound *site*: per tape binding `param` (string index or NONE), pair flag bit 1 "dst is a string index", a flag distinguishing "no map written" from "empty map written" (the two now differ), and `exits` as blob-relative code offsets with a `u8` count, like a raw descriptor's. A v3 reader already rejects reserved flag bits, so an old linker refuses rather than misreads. The writer picks the lowest version: an object with no interface, no symbolic entries and no exits stays v3. MX unchanged (descriptors already carry exits). The `.tmx.map` sidecar's `MapBinding` gains `exits`, additively.

Sketch, on the shape of `codegen.rs`'s `a5_routine_call_across_alphabets` split into two units:

```
; mylib.tmc → tmt compile -S
.routine mylib::plusOne, tapes=1, alpha=(3)
.param  num, ('_', '0', '1')
.func mylib::plusOne
inc:    rd
        mtc     T0
        djmp    D0
inc__0: wrmv    [1], [<]
        jmp     inc
inc__1: wrmv    [2], [.]
        ret

; mylib.tmh → tmt interface mylib.tmc
export alphabet bits { '_', '0', '1' }
export alphabet wide { '_', 'a', 'b', '0', '1' }
export map wideToBits: wide -> bits { '0' -> '0', '1' -> '1' }
namespace mylib {
  ? Add one to the binary number under the head.
  export routine plusOne(tape num: bits writes { '0', '1' });
}

; app.tmc — compiled by `build` with mylib's declarations, or `tmt compile --extern mylib.tmh`
use mylib::bits, mylib::wide, mylib::wideToBits;
machine {
  tape ctl:  bits;
  tape data: wide;
  entry state main {
    ['1', *] -> call mylib::plusOne(num = data with map wideToBits) then done;
    [*, *]   -> move [>, .] goto main;
  }
  state done { [*, *] -> stop; }
}

; app.tmo, the call site — symbolic on the callee side only
main__0:
        call    mylib::plusOne [num: 1{3->'0', 4->'1'}]
        jmp     done
```

```
mylib.tmo   header version 4, flags bit1 signatures, bit5 interface
            signatures  blob 0: arity 1, cards (3)
            interface   blob 0: params ("num"), glyphs (("_","0","1")), writes (("0","1")), exits 0
                        alphabets: "bits" → ("_","0","1"), "wide" → ("_","a","b","0","1")
                        graphs: (none exported here; a library graph would list name + CRC-32)

app.tmo     symbols     main Defined{blob 0}; mylib::plusOne External
            grafted     (none; a spliced library graph would list name + the digest spliced)
            bound sites blob 0, offset <hole>, symbol mylib::plusOne
                        tape binding: param "num", caller tape 1, map: written
                          src 3 -> dst "0"  (flags: dst-is-label)
                          src 4 -> dst "1"  (flags: dst-is-label)
                        exits: none
```

`tmt link app.tmo -l mylib` resolves `num` → position 0, `'0'` → 1, `'1'` → 2, and the engine receives `[1{3->1, 4->2}]` as today; the image is indistinguishable from the in-unit case. Without the declarations, `app.tmc` compiles identically except that the imports cannot be resolved — the author declares the alphabets and the map locally instead, and the link-time check of item 4 stands guard.

**Linker.** A pre-pass before the composition engine resolves symbolic sites against the callee's interface (`FuncRef` gains `interface: Option<&Interface>`): parameter name → position, bindings reordered into the callee's tape order, label → index; an imported alphabet's glyph list recorded by the compiler is compared with the exporting object's. New `BadBinding` cases: callee carries no interface ("only a transparent call can reach it" — replaces `external-binding-unsupported` for that case), unknown parameter, unknown glyph, missing or extra parameter, imported alphabet differs from the object's. A sibling check over graft provenance: for every recorded library graft whose exporting object is in the link, the digests must agree, else a `GraftDrift` error naming the graph, the consumer and the library; a graph whose exporter is not in the link (header-only library) is not checked. A header's `noreturn` is likewise checked against the object's `returns` bit. **Link warnings get an infrastructure they lack today** — the report has only structural fields and prints under `-v`: `LinkReport` gains `diagnostics` (code, message, site as function + offset, source line under `-g`), arch-agnostic like the rest of the report; the codes join the shared allow namespace as its fifth surface (`glyph-mismatch`, `narrow-alphabet`, …), so `lint.allow` in the manifest and `--allow CODE` on `link`/`build` suppress them with no new manifest key and no `-Wno-`; errors (`graft-drift`, a wider callee) are outside the namespace and cannot be suppressed; warnings print always, in the compile warning format; `-Werror` appears on `link` and covers both stages of `build`; the codes enter the same registry-versus-docs set-compare as error codes. Plain-site check for item 4, and the same check on a bound site whose map is omitted: arity and cardinalities of the callee against the caller's bands always; when both sides carry interfaces, glyphs positionally. A callee wider in alphabet or tape count is an error; narrower in tape count is silent; narrower in alphabet, or same-size with differing glyphs, is a warning in the link report naming the site, both alphabets and the first differing position, promotable with `-Werror`. An explicit map — the empty `with map { }` included — silences the glyph comparison for that binding; a global `-Wno-`/manifest allow is the legacy escape. Frames: the directory dedup key includes exits; synthesized descriptors with exits become address-dependent and are patched in layout by the same path raw-descriptor exits take today (`engine.rs:925`). Mono: stamp key `(routine, composite, exits, then)` for exit-bearing sites, `jmp` entry and the `ret`/`retx` rewrite per P2; exit-free sites unchanged. Hybrid per P4: the classifier groups exit-bearing bijection sites per `(routine, composite)` across the reachable set — `mono_stamps` reports the ones it meets inside copies, with their bindings pre-composed — sizes the body and the would-be descriptors, and routes a group to frames when sharing saves bytes, otherwise seeds mono; the decision is printed in the link report. The everything-matrix gains exit-bearing programs, including one where the same routine is reached from one site (hybrid splices) and from three (hybrid shares), all three mechanisms agreeing on tape and steps.

### Surfaces the arc also touches

**DAP on `jmp`-entered copies.** Under mono an exit-bearing site enters its per-site copy by `jmp` (P2), so while IP is inside the copy the return stack carries no frame for the caller: the stack shows the copy — openable in the library's source, since a stamp inherits provenance — *in place of* the caller, and the caller reappears after `retx → jmp exit_k`; a plain `stepOut` by stack depth would leave the caller, not the copy. Default behaviour (**A**): shown as it is, documented in `docs/dap.md` as "an exit-bearing site under mono behaves like a splice"; the `.tmx.map` sidecar records the relation "copy X un-outlined at site S of function F"; the adapter uses that record to make `stepOut` from a copy stop at the site's exits instead of the caller's return. Opt-in mode (**B**, a launch argument, say `syntheticFrames: true`): from the same record the adapter synthesizes a read-only caller frame `F` under the copy's frame, positioned at the site, so the stack reads as under frames; `setVariable` and `restartFrame` on a synthesized frame are refused, since it has no return address. Both modes pinned by a DAP test that steps into, through and out of a copy under all three mechanisms.

**`.tmh` as a file kind.** `bind_service` routes `.tmh` (case-insensitively, like the others) to the `.tmc` language service in declarations-only mode: hover, navigation, completion and diagnostics over declarations, no execution-related checks. A bare `lint`/`fmt` in manifest mode includes the target's `.tmh` files.

**wasm.** `Toolchain.build` compiles one source and links the embedded stdlib; alphabet and map imports from `std.tmh` and library-graph grafts from it work with no API change, the embedded header being read exactly as in the CLI. `--nostdlib` and `--extern` have no browser counterpart in this arc. `.tmh` is not added as a `Lang` for browser lint/format; `stdlibSource` stays for line resolution; the stdlib object pin is re-checked.

### Folded in from #121 (ratified 2026-09-13)

The completeness analysis (#121, three probe programs under `docs/superpowers/probes/2026-09-13-tmc-completeness/`) settled five lines; three add to this arc because they touch the same interface record, header and grammar bump.

**Head-position contracts — `enters` / `leaves`.** Two clauses per signature tape parameter, canonical order after `writes`/`preserves`, same element grammar (glyphs, ranges, sets): `tape num: symbols writes { '0', '1' } enters { '$' } leaves { '$' }`. Two new reserved words (`entry` is taken, `exit` collides with the exit count). Semantics and checks:
- *Static, on the callee:* `enters` must be a subset of what the entry state accepts on that tape (the cell sets `state-may-trap` already computes; exact on one tape, product-bounded on several), else `enters-not-accepted` naming the state and the missing glyph. `leaves` is checked statically where inference is exact — exit rows without a move on that tape (matched cell, or the written glyph) — else `leaves-outside-contract`; rows with a move are left to the runtime check. Neither clause is inferred when absent: absent = no promise, as with `writes`.
- *Runtime, in debug builds:* the compiler synthesizes one check state per tape at the routine's entry (`<routine>__enters_<tape>`: rows for the declared set → the real entry; catch-all → `trap #2`) and one before every way out (`… return` / `goto <state param>` rewritten to `goto <routine>__leaves_<tape>`, which reads and returns or traps), so the check reads the real cell after any move. Chained per tape, `|set| + 1` rows each, no product. **`trap #2 = contract`** is a new named trap kind in core and the ISA; `tmt run` reports the routine, tape, clause and offending glyph, `-g` maps it to the signature line, DAP stops with reason `contract`.
- *Stripping:* a new `--strip-asserts` on `compile`/`build` (independent of `--strip-debugger`, so `brk` and contract checks can be dropped separately); `--release` becomes `-O1 --strip-debugger --strip-asserts`; manifest profiles gain `strip-asserts` — **`tmt.json` `project` schema 0.2 → 0.3**, the arc's one manifest change. Without either clause codegen emits nothing new: `-O0` bit identity holds.
- *Optional by construction, never empty.* Absence of a clause is absence of a promise, exactly as with `writes`: no static check, no synthesized state, nothing inferred, the interface field is `None`, `.param` carries no suffix, and `enters-unmet` never fires against a callee without `enters` while a `then` after a callee without `leaves` flows the whole alphabet. An **empty** clause is meaningless — `enters {}` would say no glyph may be under the head on entry, `leaves {}` that no `return` is possible — and is the compile error `empty-head-clause`; the object reader rejects an empty present list as `Malformed`, so `Some(vec![])` never exists in a `RoutineInterface`. (`writes {}` keeps its meaning, "writes nowhere"; it is a different kind of claim.)
- *Carrier:* `RoutineInterface` gains `enters: Vec<Option<Vec<String>>>` and `leaves: Vec<Option<Vec<String>>>` (per tape; `None` = no clause, `Some` is non-empty), `.param` gains `[, enters=(…)][, leaves=(…)]`, headers carry them, `tmt interface` prints them. Every stdlib tape is annotated from its `?` lines, which stop being the sole carrier of the contract; the probe showed inference sharpening two of them.
- *Why the runtime check is the authority:* static inference loses everything after a `move` and widens through one-way collapse maps (`invertNumber`'s exit would infer as `{'_','^','$'}`); the assert reads the actual cell.
- *The static site check, as a lint — `enters-unmet`, default-on, no quickfix.* A forward dataflow per world and tape over "where the head may be": seeded by the world's own `enters` (whole alphabet without one); after `then s` the callee's declared `leaves` projected through the map's read preimage (whole alphabet without one); after `goto s` the row's post-glyph (matched cell without a move, the written glyph after a write, whole alphabet after a move); union to a fixpoint. At every `call`/`bind` whose callee declares `enters`, the caller's set at that row, intersected with the pattern cell and projected forward through the map, must be a subset of the callee's `enters`, else a finding naming both sets and the offending glyphs. Over-approximation is stated in the message ("may be on"); the assert stays the authority, which is why this is a warning-tier lint and not an error. It finds the commonest mistake before the first run — `[*] -> call plusOne(…)` in a machine's entry state, where the head is unconstrained — and it sees every path at once where the assert sees one. It lives in the compiler beside the footprint fixpoint (same shape, no write-back projection), reads headers like every other declaration, and runs in the editor through the overlay. Phase 3, right after the clauses.

**Open bindings — `*` in a map, the `opaque` bit.** `with map { 'a'->'a', 'b'->'b', * }` (and `with map { * }`) means "every unlisted caller symbol is opaque": the linker maps it one-way onto the index equal to the callee's cardinality, an index no callee row names, so only a `*` row matches it and only `-` keeps it; the callee cannot name it (`* as v` is already the `wildcard-binding` error, so no substitution can copy it). Without `*` a map stays closed as today. The probe proved the machine already runs this under `mono` and `frames` with a hand-written descriptor — no VM and no descriptor-format change; the linker stops turning unlisted symbols into holes for open bindings (`compose.rs` closed rule, `stamp.rs` trap rows, `engine.rs` dense map) and mono keeps the callee's `*` row. Record: one `open` flag bit on the tape binding; `.tma` spells it `[t: 1{3->'0', *}]`. Safety: the compiler infers per tape whether every state that reads it has a `*` cell there, exports the bit in the interface (`.param … opaque`, hand-written in `.tma`, never spelled in `.tmc`), and the linker **refuses** an open binding into a tape without it (`open-binding-unsupported`, naming the state lacking a `*` row). `enters` sets are over named glyphs; a routine meant to be entered anywhere declares none.

**Named glyph sets — `set`.** `set NAME { elements }`: literals, ranges and other sets (union, cycle-checked); namespaced, `export`able, `use`-importable, carried in `.tmh` as a declaration; legal in an `alphabet` body (expands in place, so `digits ⊆ dec` by construction), in every contract clause, and in a pattern cell with or without `as`; not in a write cell (a write is one symbol; `{d}` writes what matched) and never as a tape type (no index space, no blank). Expands before IR like a range; the object never sees it. One reserved word, `set` (no collision in the corpus). Lint `unused-set` beside `unused-alphabet`. **Strictness, for ranges too:** a set member, a range endpoint's expansion, or a single glyph outside the tape's alphabet in a pattern cell or clause is an **error** (`set-outside-alphabet` / `range-outside-alphabet`) — the silent per-alternative drop and the `empty-expansion` warning go; the corpus has no partial range. **`char-arithmetic` is fixed alongside:** foldability of a binding is decided by the symbol's label being numeric, not by the literal's quotes — `'0'` and `0` are one symbol, so `['0'..'8' as d] -> write [{d+1}]` folds like `[0..8 as d]`.

**Settled without a change.** Trap behaviour as a clause (line 4): only `NoTransition` is decidable, as "may", and the stdlib's partial states are deliberate; a `NoTransition` on bad input is either an `enters` violation (caught by the assert, named) or a promise the body does not keep (caught by `enters-not-accepted`); `state-may-trap` stays opt-in for authors. Representations (line 5): tape shape is a runtime property of contents — a regular language over the band — so it is a #30 test assertion (`num ~ "^\^[01]+\$$"`), not a type; alphabet import, named maps and `enters`/`leaves` cover the rest.

**Version and gate deltas from this section:** reserved words 27 → 30 (`enters`, `leaves`, `set`); `tmt.json` `project` 0.2 → 0.3 (`strip-asserts`); trap kind `#2`; error codes `enters-not-accepted`, `leaves-outside-contract`, `empty-head-clause`, `set-outside-alphabet`, `range-outside-alphabet`, `open-binding-unsupported`; lints `unused-set`, `unreachable-continuation`, `duplicate-graft-instance`, `enters-unmet`; `--strip-asserts` on `compile`/`build` in the completions registry, `cli.md` and the man page; the everything-matrix gains an open-binding program and a contract-assert program (trap under debug, clean under `--strip-asserts`, both mechanisms).

### Disposition

One arc, no follow-ups. This issue, #118 and the three additions from #121 (head contracts, open bindings, named sets) are implemented together as the change above and both close when it lands: the interface section, symbolic bound sites and exit vectors (items 1, 4, `state-param-continuation-unsupported`), headers (`.tmh` with graph bodies, `tmt interface`, `std.tmh`, `--extern`, `--nostdlib` on `compile`), alphabet import with qualified alphabet references, named maps, the two lints, the multi-exit `outline` fold and the hybrid fold rule (#118 form C, folded wherever the sites are), and the hygiene that rides along — `undefined-graph` and `unresolved-alphabet` split into their two cases, `graft-call-unsupported` reworded, the same-glyphs-same-order text moved into `language.md` with the lint pointer fixed, the "composition engine not yet online" comments retired (`compiler.rs:270-279`, `:4380-4382`), and the editor seam closed by the overlay. The four phases above are commit ordering inside the arc, not separate deliverables; the release is one.

Deliberately not built, recorded with their sketches: the compile-time splice of a call-bearing graph (item 3); partial binding (5c, path open); private tapes on routines (5a).
